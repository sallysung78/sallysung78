# 앱 개발 · 유료 출시 · 수익화 실전 가이드

> **대상**: AI로 UI(화면)까지는 만들어 봤지만, 앱을 빌드하고 스토어에 올려 돈을 받아본 적이 없는 사람
> **목표**: 유료 앱(Paid App)으로 App Store / Google Play에 출시하고 첫 정산을 받는 것
> **작성 기준일**: 2026-09 (수수료·비용은 변경될 수 있으니 출시 직전에 공식 페이지에서 한 번 더 확인)

---

## 0. 먼저 알아야 할 현실 3가지

1. **UI는 앱의 20%다.** 화면은 있지만 "데이터 저장, 화면 간 이동, 오류 처리, 결제, 빌드, 심사"가 아직 없다. 이 문서는 나머지 80%를 순서대로 채우는 절차다.
2. **유료 앱은 가장 팔기 어려운 모델이다.** 설치 전에 돈을 내야 하므로 전환율이 매우 낮다(보통 1% 미만). 그래도 "광고 없이 한 번 결제로 끝"이라는 장점이 있어 도구형·유틸리티·교육 앱에는 통한다. 대안(무료 + 인앱결제/구독)은 8장에서 비교한다.
3. **개발보다 "계정·서류·심사"에 시간이 더 든다.** 애플 개발자 등록, 구글 테스트 의무 기간, 개인정보처리방침 등 개발 외 작업이 전체 일정의 절반이다. 그래서 **개발자 계정은 1단계에서 바로 신청**한다.

## 2. 1단계 — 개발자 계정 만들기 (가장 먼저!)

승인에 시간이 걸리므로 개발을 시작하기 전에 신청한다.

### 2-1. Apple Developer Program

- **비용**: 연 $99 (한국 결제 시 약 129,000원/년, 매년 갱신)
- **신청 방법**: iPhone/iPad의 "Apple Developer" 앱 또는 developer.apple.com → Apple ID로 로그인 → 본인 확인(신분증) → 결제
- **개인 vs 조직(법인/사업자)**
  - **개인**: 신분증만 있으면 됨. 스토어에 **본명**이 판매자로 표시됨.
  - **조직**: 사업자등록 + **D-U-N-S 번호**(무료, 발급 1~2주) 필요. 스토어에 회사명 표시.
  - 처음이면 **개인**으로 시작하고, 나중에 사업자를 내면 조직으로 전환 가능.
- **승인 기간**: 보통 1~2일, 길면 1주

### 2-2. Google Play Console

- **비용**: **1회 $25** (평생, 갱신 없음)
- **신청 방법**: play.google.com/console → Google 계정으로 로그인 → 신분증 인증 → 결제
- **⚠️ 개인 계정의 핵심 제약 (2023년 11월 이후 생성 계정)**
  - 프로덕션(실제 출시) 전에 **비공개 테스트를 최소 12명의 테스터로 14일 연속** 진행해야 한다.
  - 테스터를 미리 모아두지 않으면 출시가 2주 이상 밀린다. → 6장에서 테스터 모집 방법 설명
- **조직 계정**: 사업자등록 + D-U-N-S 번호 필요, 위 테스트 의무는 없음

### 2-3. (선택) 원스토어

- 한국 전용 마켓. 수수료가 낮고(기본 20%) 국내 안드로이드 사용자 일부가 사용. 처음엔 생략해도 됨.

## 3. 2단계 — 기획 확정: "무엇을, 얼마에"

AI로 만든 UI를 보면서 아래를 A4 한 장으로 정리한다. 이게 없으면 개발 중에 계속 흔들린다.

### 3-1. MVP(최소 기능 제품) 범위 정하기

- 앱이 해결하는 문제 **한 문장** ("~하는 사람이 ~를 3초 만에 하게 해준다")
- 화면별로 **"이 화면에서 사용자가 하는 행동"**과 **"저장되는 데이터"**를 적는다
- 기능을 3등급으로 나눈다
  - **필수 (v1.0)**: 이게 없으면 앱이 아니다
  - **있으면 좋음 (v1.1)**: 출시 후 첫 업데이트
  - **나중에**: 사용자가 요청하면
- **v1.0에 3~5개 기능만 넣는다.** 초보자의 90%는 여기서 욕심을 부려 출시를 못 한다.

### 3-2. 유료 앱 가격 정하기

- 스토어는 정해진 **가격 티어**에서 고르게 되어 있다 (예: ₩1,100 / ₩2,200 / ₩4,400 / ₩6,600 / ₩11,000 …)
- 초보자 권장: **₩2,200 ~ ₩6,600** 사이. 너무 싸면 "싸구려"로 보이고, 너무 비싸면 리뷰가 없는 신규 앱은 안 팔린다
- **경쟁 앱 3개**의 가격·리뷰·기능을 표로 비교해 본다 (스토어에서 검색만 하면 됨)
- 출시 초기 1~2주는 **할인가(예: 정가 ₩6,600 → 출시 기념 ₩3,300)**로 초기 리뷰를 모으는 전략이 흔함

### 3-3. 내가 받는 실수령액 (수수료 구조)

| 마켓 | 기본 수수료 | 소규모 개발자 감면 |
|---|---|---|
| App Store | 30% | **15%** — 연 매출 $100만 이하 시 "App Store Small Business Program" 신청(무료, 승인 후 적용) |
| Google Play | 30% | **15%** — 연 매출 첫 $100만까지 자동 적용 |
| 원스토어 | 20% | (별도 프로모션 있음) |

- 예: ₩4,400 앱 → 마켓 수수료 15% 제외 → 부가세 처리 후 **약 ₩3,400 내외**가 정산됨 (국가별 세금 처리 방식에 따라 조금씩 다름)
- **Small Business Program은 애플 사이트에서 직접 신청해야 한다.** 신청 안 하면 30% 뗀다. 계정 승인되면 바로 신청할 것.

## 4. 3단계 — 기술 스택 선택과 환경 세팅

AI로 UI를 만들었다면 아마 웹(HTML/React) 또는 Flutter/React Native 코드일 것이다. **지금 가진 코드가 무엇인지**에 따라 경로가 갈린다.

### 4-1. 어떤 코드를 갖고 있나?

| 가진 것 | 추천 경로 | 이유 |
|---|---|---|
| Flutter (Dart) 코드 | 그대로 Flutter로 진행 | iOS·Android 동시 빌드, AI가 코드 잘 짬 |
| React Native / Expo 코드 | **Expo** 로 진행 | 클라우드 빌드(EAS)로 **Mac 없이도 iOS 빌드 가능** |
| 웹 HTML/React 코드 | **Capacitor**로 감싸거나, Expo로 다시 작성 | 웹뷰 앱은 애플 심사에서 거절 위험 있음(4.2 Minimum Functionality). 네이티브 기능이 있어야 통과 |
| Swift/SwiftUI 코드 | iOS 전용으로 먼저 출시 | Android는 나중에 |
| 아직 그림(디자인)만 있음 | **Flutter 또는 Expo** 중 하나 골라 AI에게 화면 재생성 요청 | 처음부터 앱 프레임워크로 시작하는 게 빠름 |

**초보자 최종 추천: Expo(React Native) 또는 Flutter.** 둘 다 무료, 문서 많음, AI 코드 생성 품질 좋음. 웹 경험이 있으면 Expo, 없으면 Flutter.

### 4-2. Mac 문제 (iOS 출시의 최대 장벽)

iOS 앱은 **최종 빌드와 업로드에 macOS + Xcode**가 필요하다. 선택지:

| 방법 | 비용 | 장단점 |
|---|---|---|
| 중고 Mac mini (M1 이상) | 약 40~70만 원 (1회) | 가장 확실. 나중에 되팔 수 있음 |
| Expo EAS Build (클라우드) | 무료 티어 있음, 유료 플랜 월 수만 원 | Windows에서도 iOS 빌드·제출 가능. Expo 쓸 때만 |
| Codemagic / Bitrise 등 CI 서비스 | 무료 티어 있음 | Flutter도 지원. 설정이 조금 복잡 |
| 안드로이드 먼저 출시, iOS는 나중에 | 0원 | 검증 후 Mac 구입 결정. **초보자에게 현실적** |

### 4-3. 로컬 개발 환경 (무료)

- **에디터**: VS Code (또는 Cursor 같은 AI 에디터)
- **Android**: Android Studio 설치 → 에뮬레이터 + 실제 폰(개발자 모드 켜기)
- **iOS** (Mac 있을 때): Xcode 설치 → 시뮬레이터 + 실제 iPhone
- **버전 관리**: Git + GitHub (이미 쓰고 있음). **매일 커밋** 습관을 들인다.
- **실제 기기 테스트 필수**: 에뮬레이터에서 되던 게 실제 폰에서 안 되는 경우가 매우 많다.

### 4-4. 백엔드(서버)가 필요한가?

- **필요 없는 경우**: 메모, 계산기, 타이머, 오프라인 도구 → 폰 안에 저장(SQLite / 로컬 저장소). **유료 앱은 이 형태가 가장 좋다** (서버비 0원, 개인정보 이슈 최소)
- **필요한 경우**: 로그인, 기기 간 동기화, 사용자끼리 공유 → **Firebase** 또는 **Supabase** 무료 티어로 시작 (월 수천 명까지 0원)
- 서버가 필요하면 개인정보처리방침·보안 부담이 크게 늘어난다. **v1.0은 서버 없이** 갈 수 있는지 먼저 고민.

## 5. 4단계 — 기능 개발: UI에 생명 넣기

이미 있는 화면에 아래 순서로 "동작"을 붙인다. AI에게 요청할 때도 이 순서대로 하나씩 시킨다.

1. **화면 이동(네비게이션)**: 모든 화면이 실제로 연결되게. 뒤로가기 동작 확인
2. **상태 관리**: 버튼을 누르면 화면이 바뀌는 것. (Flutter: Riverpod/Provider, Expo: Zustand/Context)
3. **데이터 저장**: 앱을 껐다 켜도 데이터가 남게. (로컬 DB 또는 Firebase)
4. **입력 검증·오류 처리**: 빈 값, 잘못된 값, 네트워크 끊김 시 앱이 죽지 않게
5. **빈 화면·로딩 화면**: 데이터가 없을 때, 불러오는 중일 때 보여줄 UI
6. **설정 화면**: 앱 버전, 문의(이메일), 개인정보처리방침 링크, 오픈소스 라이선스 → **심사 필수 항목**
7. **다크모드·글자 크기 대응**: 애플 심사에서 깨진 UI는 거절 사유
8. **앱 아이콘·스플래시 화면** 적용
9. **분석 도구(선택)**: Firebase Analytics 무료. 어떤 화면을 많이 쓰는지 봐야 업데이트 방향이 잡힘

**AI에게 시키는 요령**
- "전체 앱 만들어줘" ❌ → "이 화면에서 저장 버튼 누르면 SQLite에 저장되게 해줘" ⭕
- 오류 메시지는 **전문 복사해서** 붙여넣기
- 한 번에 한 기능. 되면 커밋. 안 되면 되돌리기(`git checkout .`)

## 6. 5단계 — 출시 준비물 (개발만큼 중요)

### 6-1. 스토어 등록에 필요한 것 체크리스트

| 항목 | App Store | Google Play | 만드는 법 |
|---|---|---|---|
| 앱 아이콘 | 1024×1024 PNG (투명 X) | 512×512 PNG | Figma/Canva 무료, 또는 AI 생성 후 손보기 |
| 스크린샷 | 6.7" (1290×2796) 필수, 다른 크기 선택 | 폰 2장 이상 (1080×1920 권장) | 실제 앱 캡처 → Canva로 텍스트 얹기 |
| 그래픽 이미지 | - | 1024×500 (필수) | Canva |
| 앱 이름 | 30자 | 30자 | 검색 키워드 포함 |
| 부제/짧은 설명 | 30자 | 80자 | 핵심 가치 한 줄 |
| 설명 | 4,000자 | 4,000자 | 기능 → 누구에게 → 왜 유료인지 |
| 키워드 | 100자 (쉼표 구분) | 설명에 자연스럽게 포함 | 경쟁 앱 이름·기능어 |
| **개인정보처리방침 URL** | **필수** | **필수** | 아래 6-2 |
| 지원 URL / 이메일 | 필수 | 필수 이메일 | GitHub Pages 또는 노션 공개 페이지 |
| 연령 등급 | 설문 응답 | 설문 응답 | 5분 |
| 데이터 수집 고지 | App Privacy 항목 | 데이터 보안 섹션 | 수집 안 하면 "수집 안 함" 선택 |

### 6-2. 개인정보처리방침 (무료로 만들기)

- 데이터를 전혀 수집하지 않아도 **반드시 URL이 있어야** 한다
- 방법: GitHub 저장소에 `privacy.md` 작성 → **GitHub Pages**로 무료 호스팅 → URL 사용
- 내용: 수집 항목(없으면 "없음"), 사용 목적, 보관 기간, 제3자 제공(분석 도구 쓰면 명시), 문의처
- 무료 생성기(예: app-privacy-policy-generator 계열)로 초안 만들고 한국어로 다듬기
- Firebase Analytics 등을 쓰면 "Google에 익명 사용 통계 제공"을 반드시 명시

### 6-3. 한국 출시 시 추가로 확인할 것

- **게임이면**: 게임물관리위원회 등급분류 필요 (자체등급분류 사업자인 애플·구글을 통해 자동 처리되는 경우가 대부분이나, 청소년이용불가 등급은 별도)
- **사업자등록**: 개인도 출시는 가능하지만, 수익이 꾸준히 발생하면 사업자등록(간이과세)이 유리. 세무사 30분 상담(무료~5만 원) 추천
- **통신판매업 신고**: 앱 마켓을 통한 판매는 마켓이 통신판매중개자이므로 개인 개발자 단독 신고 의무 여부에 해석 차이가 있음. 사업자 전환 시 세무사/구청에 확인
- **종합소득세**: 애플·구글 정산금은 소득이므로 다음 해 5월 신고 대상. 정산 내역 PDF는 매달 저장해 둘 것

## 7. 6단계 — 테스트 (여기서 구글 2주가 걸린다)

### 7-1. Google Play — 비공개 테스트 (개인 계정 필수)

1. Play Console → 테스트 → **비공개 테스트** 트랙 생성
2. AAB(빌드 파일) 업로드
3. **테스터 12명 이상**의 Gmail을 이메일 목록으로 등록
4. 테스터에게 초대 링크 전달 → **설치 후 14일간 유지**하도록 부탁 (중간에 삭제하면 카운트 안 됨)
5. 14일 후 Console에서 **"프로덕션 액세스 신청"** → 설문 작성 → 승인(수일)
6. 승인 후 프로덕션 출시 가능

**테스터 12명 모으는 법**: 가족·친구·직장 동료 + 카카오 오픈채팅 "앱 테스터 품앗이" 방 + 커뮤니티(디스콰이엇, 인디해커스 한국) 상호 테스트. **1단계에서 계정 만들 때부터 모집 시작**해야 일정이 안 밀린다.

### 7-2. App Store — TestFlight

1. App Store Connect에 빌드 업로드 (Xcode 또는 EAS Submit)
2. **내부 테스트**: 본인 포함 최대 100명, 심사 없음, 즉시 가능
3. **외부 테스트**: 최대 10,000명, 간단한 심사(1일 내외) 후 링크 공유
4. 의무 기간 없음. 하지만 **최소 5명, 1주일**은 돌려보고 크래시를 잡을 것

### 7-3. 스스로 하는 테스트 체크리스트

- [ ] 앱 최초 설치 → 삭제 → 재설치 시 정상 동작
- [ ] 비행기 모드에서 앱이 죽지 않음
- [ ] 화면 회전, 다크모드, 큰 글씨 설정
- [ ] 저사양 폰(3~4년 된 폰)에서 버벅임 확인
- [ ] 모든 버튼 눌러보기 (막다른 화면 없는지)
- [ ] 설정 → 개인정보처리방침 링크가 실제로 열리는지

## 8. 7단계 — 유료 판매 계약 · 세금 · 정산 정보 (돈 받으려면 필수)

빌드가 아무리 완벽해도 이게 없으면 **유료 앱 심사 제출 자체가 막힌다.**

### 8-1. App Store Connect

1. **계약/세금/금융거래(Agreements, Tax, and Banking)** 메뉴 → **"Paid Apps Agreement" 동의** (무료 앱 계약과 별개)
2. **은행 정보**: 본인 명의 계좌 (SWIFT 코드 필요 — 은행 앱/고객센터에서 확인, 예: 국민 CZNBKRSE)
3. **세금 양식**: 미국 세금 양식(W-8BEN, 개인) 온라인 작성. 미국 외 국가 판매분에는 영향 없음. 한국은 별도 세금 정보 입력 요구 시 안내에 따라 작성
4. **Small Business Program 신청** (3-3 참고) — 계약 동의 후 별도 페이지에서 신청
5. **정산 주기**: 매월 마감 후 약 45일 뒤 지급, 최소 지급액 있음

### 8-2. Google Play Console

1. **결제 프로필(Payments profile)** 생성 → 개인 정보·주소 입력
2. **은행 계좌** 등록 → 구글이 소액 입금으로 검증 (1~3일)
3. **세금 정보** 입력 (한국 거주자 개인)
4. **판매 국가·가격** 설정: 기본 가격(USD 또는 KRW) 넣으면 국가별 자동 환산. 한국 가격은 직접 다듬을 것
5. **정산 주기**: 매월 15일경 전월 수익 지급, 최소 지급액 있음

### 8-3. 유료 앱 vs 다른 수익 모델 (출시 전 마지막 점검)

| 모델 | 장점 | 단점 | 이런 앱에 적합 |
|---|---|---|---|
| **유료 앱 (선불)** | 구현 가장 쉬움(결제 코드 0줄), 광고 없음, 리뷰 품질 높음 | 전환율 매우 낮음, 환불 요청 잦음, 나중에 무료로 바꾸면 기존 구매자 반발 | 오프라인 도구, 전문 계산기, 교육, 틈새 유틸 |
| 무료 + 인앱결제(1회) | 써보고 결제 → 전환율 높음 | 결제 코드 구현 필요 (RevenueCat 쓰면 반나절) | 대부분의 도구형 앱 |
| 무료 + 구독 | 반복 수익, 앱스토어 노출 유리 | 계속 가치를 줘야 함, 해지율 관리 | 콘텐츠·데이터 동기화 앱 |
| 무료 + 광고 | 진입 장벽 0 | 유료 앱보다 사용자 1만 명은 있어야 의미 있음 | 캐주얼·대중 앱 |

**전문가 조언**: 유료 앱으로 가더라도 **"라이트(무료, 기능 제한) + 프로(유료)" 두 개 앱**을 올리거나, 처음부터 **무료 + 인앱결제 "프로 잠금해제"(1회 결제)** 로 만드는 게 매출이 2~5배 높은 것이 일반적이다. 유료 앱으로 결정했다면 **스토어 스크린샷과 설명에 "왜 돈을 낼 가치가 있는지"를 첫 두 줄에** 써야 한다. 인앱결제 라이브러리는 **RevenueCat**(월 매출 일정 금액까지 무료)이 초보자에게 가장 쉽다.

## 9. 8단계 — 심사 제출과 출시

### 9-1. App Store 심사

- **소요**: 보통 24~48시간, 첫 앱은 최대 1주
- **자주 거절되는 이유 (초보자 TOP 5)**
  1. **2.1 앱 완성도**: 크래시, 빈 화면, 안 되는 버튼 → 7-3 체크리스트로 예방
  2. **4.2 최소 기능**: 웹사이트를 감싼 것뿐 / 기능이 너무 단순 → 네이티브 기능(알림, 위젯, 오프라인 등) 추가
  3. **5.1.1 개인정보**: 정책 URL 없음, 불필요한 권한 요청 → 권한은 꼭 필요한 것만, 요청 문구에 이유 명시
  4. **2.3 메타데이터**: 스크린샷이 실제 앱과 다름, 설명에 다른 플랫폼 언급
  5. **3.1.1 결제**: 앱 안에서 외부 결제 링크 → 유료 앱은 해당 없음. 절대 "PC 버전은 더 싸요" 같은 문구 금지
- **거절되면**: Resolution Center에서 이유 확인 → 수정 → 재제출 (재심사는 보통 더 빠름). 심사관과 **정중히 영어로 설명**하면 통과되는 경우도 많음
- 팁: **심사 노트(Review Notes)**에 앱 사용법을 3줄로 적고, 로그인이 있으면 테스트 계정 필수 기재

### 9-2. Google Play 심사

- **소요**: 첫 앱 3~7일, 이후 업데이트는 수 시간~2일
- **자주 거절되는 이유**: 데이터 보안 섹션 미작성/불일치, 개인정보처리방침 URL 오류, 권한 사용 근거 부족, 앱 이름·아이콘의 상표 침해
- **단계적 출시** 기능으로 10% → 50% → 100% 순차 배포 가능 (버그 발견 시 중단)

### 9-3. 출시 당일 할 일

- [ ] 두 스토어 출시 시점 맞추기 (구글은 심사 후 "수동 출시" 옵션 선택)
- [ ] 스토어 링크를 짧은 URL로 정리 (bit.ly 등)
- [ ] 주변 10명에게 **첫날 리뷰** 부탁 (첫 리뷰 5개가 전환율을 좌우함)
- [ ] 크래시 모니터링(Firebase Crashlytics, 무료) 대시보드 켜놓기

## 10. 9단계 — 출시 후: 수익을 실제로 만드는 일

출시는 시작이다. 유료 앱은 **"발견 → 신뢰 → 구매"** 세 단계를 스토어 안에서 다 해결해야 한다.

### 10-1. ASO (스토어 검색 최적화) — 무료, 효과 큼

- 앱 이름·부제에 **사용자가 검색할 단어** 넣기 ("가계부", "타이머" 등 일반명사)
- 첫 스크린샷 1장에 앱의 가치가 다 보이게 (텍스트 1줄 + 화면)
- 리뷰 답글 달기 (애플·구글 모두 개발자 답글 가능. 응답률이 신뢰도에 영향)
- 2~4주마다 키워드 바꿔가며 다운로드 변화 관찰

### 10-2. 초기 마케팅 (0원~소액)

- 커뮤니티 소개글: 디스콰이엇, 클리앙 앱추천, 네이버 카페, 레딧(영어 지원 시)
- 유튜브·블로그에 "이 앱으로 ~하는 법" 사용법 글 3개
- 출시 기념 할인(1~2주) → "가격 인상 예정" 공지로 구매 유도
- 프로모션 코드: 애플은 버전당 100개 무료 코드 발급 가능 → 리뷰어·인플루언서에게 제공

### 10-3. 업데이트 리듬

- **첫 2주**: 크래시·리뷰 불만 즉시 수정 (1.0.1, 1.0.2 …)
- **매 4~6주**: 기능 1개 추가 + "새로운 기능" 노트 작성 (스토어 노출에 유리)
- **매년**: iOS/Android 새 버전 대응 (9~10월 iOS 대응 필수). 개발자 계정 갱신 잊지 말 것

### 10-4. 지표 보는 법 (App Store Connect / Play Console 기본 제공)

| 지표 | 건강한 수치 (유료 앱) | 낮으면 고칠 곳 |
|---|---|---|
| 노출 → 스토어 페이지 방문 | 5~10% | 아이콘, 앱 이름, 첫 스크린샷 |
| 페이지 방문 → 구매 | 1~5% | 설명 첫 두 줄, 가격, 리뷰 수 |
| 환불률 | 5% 미만 | 스크린샷이 과장됐거나 첫 사용 경험 문제 |
| 평점 | 4.3 이상 | 크래시, 리뷰 답글 |

## 13. 자주 하는 질문

**Q. 코딩을 전혀 모르는데 AI만으로 끝까지 가능한가요?**
A. 출시까지는 가능하다. 다만 **오류 메시지 읽기, Git 되돌리기, 빌드 설정 파일 위치** 정도는 익혀야 AI의 답을 적용할 수 있다. 막힐 때는 "지금 상황 + 오류 전문 + 내가 시도한 것"을 AI에게 통째로 주면 대부분 풀린다.

**Q. 아이폰만 먼저 출시하면 안 되나요?**
A. 된다. 유료 앱은 iOS 매출 비중이 훨씬 높은 경우가 많아, **iOS 먼저 → 반응 보고 Android**도 합리적이다. 단 Mac이 필요하다.

**Q. 개인 이름이 스토어에 공개되는 게 싫어요.**
A. 사업자등록 + D-U-N-S 번호로 조직 계정을 만들면 상호명이 표시된다. 개인 계정으로 시작한 뒤 전환 가능.

**Q. 유료 앱을 나중에 무료로 바꿀 수 있나요?**
A. 가능하지만 이미 산 사용자가 불만을 가진다. 반대(무료 → 유료)는 기존 설치자는 계속 무료다. 그래서 처음부터 모델을 신중히 정하라는 것.

**Q. 환불은 어떻게 처리되나요?**
A. 애플·구글이 직접 처리하고 개발자는 관여할 수 없다. 환불된 금액은 다음 정산에서 차감된다.

**Q. 세금은 얼마나 떼나요?**
A. 마켓 수수료(15~30%)와 별도로, 정산받은 금액은 소득세 신고 대상이다. 개인은 종합소득세(5월), 사업자는 부가세 신고까지. 첫 해에 세무사 상담 한 번은 꼭 받을 것.
