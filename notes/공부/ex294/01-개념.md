# 1️⃣ 개념 (Concepts)

> 시험 전체를 관통하는 핵심. YAML은 외우는 게 아니라 **틀 + 개념**으로 푼다.

---

## 🧱 공통 플레이북 뼈대 (모든 문제의 시작)
```yaml
---
- name: <play 이름>
  hosts: <target group>      # 문제에 나온 그룹 그대로
  become: true               # /etc, 패키지, 서비스, 사용자 변경이면 거의 필요
  vars_files:
    - <필요 시 vault/vars 파일>
  tasks:
    - name: <task 이름>
      ansible.builtin.<module>:
        <option>: <value>
```
- 세로 한 줄 순서: **`- name` → `hosts` → `become` → `tasks`**
- `become`: /etc·패키지·서비스·사용자 변경이면 거의 항상 필요
- `vars_files`: vault / user_list 같은 외부 변수 쓸 때
- ⚠️ 들여쓰기: `tasks:` 아래 `- ` 하나 붙이고 세 번째 글자에 맞춤. 탭 금지(공백만)

## 📁 인벤토리 (Inventory) 개념
- 정적 인벤토리 파일에는 **첫 줄 `---` 가 없다!** (플레이북과 다름)
- 그룹 정의:
```ini
[dev]
node1

[prod]
node3
node4

[webservers:children]   # 그룹 안에 그룹 포함 (children)
prod
```
- `ansible.cfg` 에 inventory / roles_path / collections_path 경로를 지정해두면 매번 안 써도 됨
```ini
[defaults]
inventory = /home/user/ansible/inventory
roles_path = /home/user/ansible/roles
collections_path = /home/user/ansible/collections

[privilege_escalation]   # 넣어두면 become 매번 안 써도 됨
become = true
```

## 📊 Facts (팩트) 개념 — ⭐ 시험 핵심
- Ansible이 호출하면 **모든 노드에서 facts 정보를 가져옴**
- 하위 계층은 **점(`.`)** 으로 구분: `ansible_facts.default_ipv4.address`
- 변수 선언 시 `ansible_facts['키']` 형태로, 대괄호 안 키는 `'   '`(따옴표)로 감쌈
- 노드의 IP를 변수로 치환 → `ansible_facts.default_ipv4.address`
- 👉 **facts 이름은 외우지 말고** `setup` 결과에서 filter/검색으로 확인 (→ 04번 파일)

## 🎭 역할(Role) 개념
- **롤은 호출당하는 쪽** → 롤 내부 YAML에는 `hosts`가 없다! (대신 `tasks/main.yml` 부터 실행)
- 롤을 쓰는 플레이북은 `tasks` 대신 **`roles:`** 로 호출
```yaml
- hosts: webservers
  roles:
    - apache
```
- **System Role** (timesync, selinux, storage, network): `tasks`가 없고 **`vars`로 변수만 지정**
  - 변수명은 외우지 말고 **README의 Example을 복사 → 값만 수정**
- 롤 설치 두 가지 방식 구분:
  - **role**: `ansible-galaxy install -r requirements.yml`
  - **collection**: `ansible-galaxy collection install <파일> -p <경로>`

## 🔐 Vault (자격 증명 모음) 개념
- 민감 변수(암호 등)를 암호화하는 파일
- 플레이북에서 `vars_files:` 로 불러옴
- 비밀번호 파일을 `ansible.cfg` 의 `vault_password_file` 에 지정하면 실행 때마다 입력 안 해도 됨
- 명령: encrypt / decrypt / view / edit / **rekey**(키 재설정)

## 🔀 조건문 · 반복 · 실패 처리 (Task Control) — 문제를 짧게 만드는 3개 문법

### when (조건)
```yaml
when: inventory_hostname in groups['dev']     # dev 그룹에서만 실행
when: ansible_lvm.vgs.research is defined      # 볼륨그룹 있을 때
when: ansible_lvm.vgs.research is undefined     # 없을 때
```
> ⚠️ `inventory_hostname`(인벤토리상 이름) vs `ansible_hostname`(팩트) 구분. 오타 주의.

### loop (반복)
```yaml
loop: "{{ users }}"          # 외부 변수 리스트 반복
loop: "{{ hw_all }}"
```

### block / rescue / always (실패 처리) — LV 문제 핵심
```yaml
tasks:
  - block:                   # 1. 정상 시도
      - lvol: { vg: research, lv: data, size: 1500m }
    rescue:                  # 2. 실패 시 (else 같은 것)
      - debug: { msg: "Could not create logical volume of that size" }
      - lvol: { vg: research, lv: data, size: 800m }
    always:                  # 3. 항상
      - debug: { msg: "Volume group not found" }
```

## 🧩 Jinja2 템플릿 개념
- `{{ }}` 출력, `{% %}` 로직, `{# #}` 주석
- `default('NONE', true)` 필터 → 값이 없으면 NONE으로 대체 (hwreport 문제 핵심)
- 호스트 반복 패턴:
```jinja
{% for host in groups['all'] %}
{{ hostvars[host]['ansible_default_ipv4']['address'] }} {{ hostvars[host]['ansible_fqdn'] }} {{ hostvars[host]['ansible_hostname'] }}
{% endfor %}
```
