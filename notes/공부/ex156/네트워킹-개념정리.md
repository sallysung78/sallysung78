# 네트워킹 개념정리 (EX156 · 약점 50%)

> VM 네트워킹 + 외부 액세스(Route/LB/NodePort) + UDN. 개념 + **꼭 외울 명령**.
> 핵심 한 줄: **웹=Route / 비웹=LB·NodePort**, **VM 노출=`virtctl expose vm`**.

## 0. 🗺️ 네트워크 구조 (계층)
```
┌── OpenShift 클러스터 ─────────────────────────────────────┐
│  ┌ 프로젝트 A (UDN) ┐   ┌ 프로젝트 B (기본) ┐               │
│  │ VM  VM  Pod      │   │ VM  VM  Pod       │              │
│  │  [UDN-A] 격리     │   │  [Pod network] 공용 │            │
│  └──────────────────┘   └───────────────────┘             │
│   가상 네트워크 (OVN-Kubernetes가 구현):                    │
│   ① Pod network(=Cluster network) 클러스터 공용(기본)       │
│   ② UDN  프로젝트 전용(선택, 격리)                          │
│   ③ Service network(172.30.x) ClusterIP·Route·LB용          │
└────────────────────────────────────────────────────────────┘
        ⇣ 위 오버레이가 아래 물리망 위에 얹힘
   [Master Node]═══ Machine network(노드 실제 IP) ═══[Worker Node]
                    API·etcd·kubelet (노드끼리 제어 트래픽)
```
| 네트워크 | 범위 | 역할 |
| --- | --- | --- |
| **Machine network** | 노드(물리) | 노드끼리 통신(API/etcd) |
| **Pod network**(=Cluster) | **클러스터 전체** | 파드/VM 통신(기본, OVN) |
| **UDN** | **프로젝트(NS)** | 격리·서브넷재사용·고정IP(선택) |
| **Service network** | 클러스터 | 서비스 가상IP |

## 1. Pod network vs UDN
- **Pod network** = 클러스터 기본 공용. 안 만들어도 모든 VM 자동 연결. (VM은 **masquerade=NAT** 바인딩)
- **UDN**(UserDefinedNetwork) = **프로젝트 전용 격리 네트워크**(선택, 4.18). 안 쓰면 Pod network가 기본.

**UDN 장점 3가지**
| 장점 | 의미 |
| --- | --- |
| 테넌트 격리 | NS마다 격리된 전용 네트워크 (여러 NS 공유=클러스터UDN, 관리자권한) |
| 일관된 IP | 여러 NS가 **같은 서브넷 재사용**해도 격리 (개발/테스트/운영) |
| **영구 IP** | VM 고정 IP, 재시작·노드이동에도 유지, **L2라 NAT 없이 마이그레이션** |
> 💡 VM에 중요 = ③ 영구 IP + NAT 없는 마이그레이션(다운타임↓).

## 2. VM 네트워크 바인딩 (primary / secondary)
```
VM
 ├ eth0 (primary, 필수 1개): Pod network→masquerade(기본) 또는 UDN
 └ eth1.. (secondary, 선택): 2차 네트워크 = Multus + NAD
```
**2차 네트워크(NAD/Multus) 종류**: Linux bridge / OVN localnet·layer2 / SR-IOV
```yaml
# VM에 2차 NIC 붙이기 (개념)
spec:
  template:
    spec:
      domain:
        devices:
          interfaces:
          - name: default
            masquerade: {}        # 파드 네트워크
          - name: bridge-net
            bridge: {}            # 2차
      networks:
      - name: default
        pod: {}
      - name: bridge-net
        multus: { networkName: my-bridge-nad }   # NAD 이름
```
> 체크: interface name ↔ network name **짝 맞아야**. masquerade는 파드 네트워크만.
> 🔴 **2차 NIC 추가 후 재부팅**(SNO는 특히). 호스트 브리지 구성은 **NMState(NNCP)**.

## 3. 🌐 외부 액세스 서비스 4종 ⭐
| 유형 | 트래픽 | 특징 |
| --- | --- | --- |
| **NodePort** | HTTP/non-HTTP | 모든 노드 포트 열림(보안 위험) |
| **LoadBalancer** | HTTP/non-HTTP | 외부 IP. 클라우드 LB / 온프렘=**MetalLB** |
| **Ingress** | HTTP/HTTPS/TLS(SNI) | k8s 표준 |
| **Route** ⭐ | HTTP/HTTPS/TLS | **OpenShift 전용**, 고유 hostname |
> 🔑 **웹(HTTP/S)=Route / 비웹(UDP·일반TCP)=LoadBalancer·NodePort.**

## 4. Route (경로)
- **전제: ClusterIP 서비스 먼저** → `oc expose service`로 Route 생성.
- **DNS 자동**: `routename-namespace.기본도메인` (예: intranet-prod.apps.mycompany.com)
- **구현**: HAProxy 라우터 포드. 와일드카드 DNS → 라우터 IP.
```bash
oc expose service/web                          # 기본(이름=web, DNS 자동)
oc expose service/web --name web --hostname web-production.apps.mycompany.com
oc get route web                               # HOST 확인
# 경로 기반(path): 같은 hostname, URL 경로로 분기
oc expose service/static --path=/static --hostname=intranet-prod.apps.mycompany.com
```
콘솔: Networking → Routes → Create Route.

## 5. 🔒 암호화 Route — TLS 종료 3종 ⭐
| 종류 | TLS 종료 위치 | 라우터→백엔드 | 인증서 |
| --- | --- | --- | --- |
| **edge** | 라우터에서 | 암호화 **안 됨** | 라우터 제공 |
| **passthrough** | 종료 안 함(그대로) | 암호화됨 | **앱이** 제공 |
| **reencrypt** | 라우터 종료 후 재암호화 | **암호화됨(전구간)** | 라우터+백엔드 |
```bash
# oc expose = 평문(HTTP)만! 암호화는 oc create route
oc create route edge --service web --hostname api.apps.acme.com   # edge|passthrough|reencrypt
#   사용자 인증서: --key, --cert
```
**Insecure traffic 정책**: None(차단) / Allow(HTTP 허용) / Redirect(HTTP→HTTPS).

## 6. ⭐⭐ VM 노출 = `virtctl expose vm` (계속 나옴! 무조건 외우기)
> VM은 `virtctl expose`가 간편 — **라벨 추가·재시작 불필요** (자동 `vm.kubevirt.io/name` 라벨 사용).

```bash
# ① VM 서비스 생성 (자주 나오는 그 명령)
virtctl expose vm hello-web --name=hello-web --type=ClusterIP --port=80 --target-port=80
# ② Route 생성 (웹이면)
oc expose service/hello-web --name=<route이름>
```
| 플래그 | 의미 |
| --- | --- |
| `--name` | 만들 서비스 이름 |
| `--type` | ClusterIP / NodePort / LoadBalancer |
| `--port` | 서비스가 받는 포트 |
| `--target-port` | VM 안 실제 포트 (생략=`--port`와 동일) |

> 수동 방식(VM에 라벨 → 재시작 → Service YAML selector)은 **virtctl expose가 대신**해줌 → 개념만.
> 앱 기본 포트: 웹 80 / HTTPS 443 / SSH 22 / RDP 3389.

**LoadBalancer 노출 + 검증**
```bash
virtctl expose vm <vm> --name=<svc> --type=LoadBalancer --port=80
oc get svc <svc>                                              # EXTERNAL-IP (pending이면 LB/MetalLB 없음)
oc get svc <svc> -o jsonpath='{.status.loadBalancer.ingress[0].ip}'
curl http://<EXTERNAL-IP>:80
```

## 8. ⚖️ LoadBalancer + MetalLB (non-HTTP 노출) ⭐

### 왜 LB/NodePort? (Route로 안 되는 것)
> **Route/Ingress = HTTP/HTTPS/TLS만.** SSH·DB(MySQL)·SMTP·POP3·IMAP·LDAP 등 **non-HTTP는 Route 불가** → **NodePort 또는 LoadBalancer** 사용.

### NodePort vs LoadBalancer
| | **NodePort** | **LoadBalancer** ⭐ |
| --- | --- | --- |
| 노출 | 모든 노드의 포트(**30000~32767**) | **고정 외부 IP** + 포트 |
| 노드 이동 시 | 노드 IP 노출 필요(보안↓), 클라우드선 IP 비영구 | **VM이 노드 옮겨도 IP 안 바뀜** |
| 권장 | 비권장 | 권장 |
> NodePort `nodePort:` 생략 시 자동 할당. 범위 밖 포트 X.

### MetalLB Operator (온프렘/베어메탈 LB)
> 클라우드 아닌 클러스터(베어메탈·SNO)는 클라우드 LB가 없음 → **MetalLB**가 LB 서비스에 외부 IP 할당.
- **모드 2종**: **L2(ARP, 기본)** = ARP로 IP 광고, 한 노드로 트래픽 / **L3(BGP)** = BGP 경로 광고, AS 번호 필요.
- 설치 = OLM, **`metallb-system`** 프로젝트. **CR 3종** (관리자가 구성):
  | CR | 역할 |
  | --- | --- |
  | **MetalLB** | 기본 인스턴스 |
  | **IPAddressPool** | LB에 줄 **IP 범위** (예: 192.168.50.20-40) |
  | **L2Advertisement** | 그 풀을 **L2(ARP)로 광고** |
```bash
oc get metallb,ipaddresspool,l2advertisement -n metallb-system
```

### VM을 LoadBalancer로 노출 (핵심)
```bash
virtctl expose vm vm1 --name=vm1-ssh --type=LoadBalancer --port=22 --target-port=22
```
- selector = **`vm.kubevirt.io/name: vm1`** (virt-launcher 포드 표준 라벨, 자동)
- **검증 순서**:
```bash
oc get svc                # EXTERNAL-IP 떴나 (MetalLB가 할당, 예 192.168.50.23)
oc get endpoints          # virt-launcher 포드 IP:포트로 확인됐나 (<none>이면 selector 불일치)
oc get vmi                # VMI IP/노드 확인
nc -vz <EXTERNAL-IP> 22   # TCP 연결 확인
ssh developer@<EXTERNAL-IP>   # 실제 접속
```

### 여러 포트 노출
- `virtctl expose`는 **`--port` 하나만** 가능. 여러 포트는 **YAML 편집**(각 포트에 **`name` 필요**).
- virtctl은 `--port-name`으로 포트 이름 지정 / 기존 서비스는 `oc edit service <svc>`.

### 콘솔: SSH over LoadBalancer
```
VM → Configuration → SSH 탭 → SSH service type = "SSH over LoadBalancer"
```
> ⚠️ 활성화 직후 **endpoint가 `<none>`**(selector 불일치)일 수 있음 → **라이브 마이그레이션**(Actions → Migration → Compute)하면 라벨 맞는 새 virt-launcher 생성 → endpoint 확인됨.
> (사전조건: Overview → Settings → SSH configuration에서 "SSH over LoadBalancer" 활성).

## 9. 🔗 멀티홈 VM (2차 네트워크 = NAD) ⭐

> **멀티홈 VM** = **2개 이상 네트워크**에 연결된 VM (기본 pod network + 보조 네트워크). 외부 스토리지·DB 네트워크 접근용.

### 전체 흐름 (역할 분담)
```
[관리자] NMState Operator → NNCP(노드에 브리지 생성) → NAD(보조 네트워크 정의)
[사용자] VM에 NAD를 새 NIC로 연결 → 재부팅(또는 핫플러그+마이그레이션)
```

### 관리자 영역 — 노드 네트워크 (NMState)
- **NMState Operator**: 노드 네트워크를 **선언적**으로 관리. CR 2개:
  | CR | 역할 |
  | --- | --- |
  | **NNCP** (NodeNetworkConfigurationPolicy) | **의도한 구성** 정의 (Linux bridge/OVS bridge/bonding/ethernet). `nodeSelector`로 대상 노드 |
  | **NNCE** (NodeNetworkConfigurationEnactment) | 각 노드의 **실행 상태 보고**, 실패 시 **롤백** + 디버깅 |
- **브리지** = VM ↔ 노드 물리 NIC 연결점. Linux bridge(소프트 스위치) / OVS bridge(+격리 등 고급).

### NAD (NetworkAttachmentDefinition)
- 노드에 브리지 만든 뒤, **NAD**로 워크로드가 그 보조 네트워크를 쓰게 함. **Multus(CNI)**가 NAD 읽어 인터페이스 연결.
- **namespace 리소스** (VM과 같은 NS의 NAD만 연결 / `default` NS의 NAD는 전체 사용 가능).
- **OVN 토폴로지 2종** (시험 포인트):
  | 토폴로지 | 의미 |
  | --- | --- |
  | **layer2** | 클러스터 **내부** 워크로드끼리만 (L2 오버레이) |
  | **localnet** | **물리 네트워크 연결** → 클러스터 **외부**와 통신 |

### VM에 2차 NIC 연결
- **콘솔**: VM → Configuration → **Network Interfaces → Add Network Interface** → Network에서 NAD 선택 → Add
- **YAML**: `interfaces`(bridge) + `networks`(multus.networkName) — **name 짝 맞아야**
```yaml
domain.devices.interfaces:
  - masquerade: {} ; name: default          # 기본 pod
  - bridge: {} ; model: virtio ; name: additional-nic   # 2차
networks:
  - name: default ; pod: {}
  - name: additional-nic                     # ↑ interface name과 일치
    multus: { networkName: br0-network }     # NAD 이름
```
> 🔴 추가 후 **VM 재시작**(실행 중) / 시작(중지) 해야 적용.

### 보조 NIC 핫플러그 (재부팅 없이)
- **bridge 바인딩 + VirtIO = 핫플러그 O** / **SR-IOV = 핫플러그 X**
- 추가 절차는 동일 → **적용은 라이브 마이그레이션**:
```bash
virtctl migrate <vm>            # 또는 콘솔 Actions → Migration → Compute
```

### 보조 NIC IP 주소
- 기본 pod network = **임시 IP**(정적 할당 불가). **정적/동적 IP 필요 → 보조 NIC(브리지)** 연결.
- **동적**: 브리지 네트워크에 **DHCP 서버** 필요.
- **정적(수동)**: **cloud-init `networkData`** (`spec.volumes.cloudInitNoCloud.networkData`)
```yaml
networkData: |
  version: 2
  ethernets:
    enp2s0:
      addresses: [ 192.168.51.150/24 ]
```
> 확인: VM **Overview 탭 → Network 섹션**에서 IP.

## 10. 🔧 SDN 기반 인프라 (CNO · DNS · CIDR)
- **SDN**(소프트웨어 정의 네트워크) = Pod network + Service network (VMware vSwitch 같은 역할).
- **CNO**(Cluster Network Operator)가 SDN 관리 → CNI 호출. 기본 **OVN-Kubernetes**(각 노드 OVS).
- **Multus 관리** = **CNAO**(Cluster Network Addons Operator), 설치 시 **HCO**(HyperConverged Operator)가 배포.
- **CIDR 확인**(관리자 권한):
```bash
oc get network/cluster -o yaml
#   clusterNetwork.cidr=10.8.0.0/14 (Pod) / serviceNetwork=172.30.0.0/16 (Service)
```
- **DNS**(DNS Operator): 서비스 = **`servicename.namespace.svc.cluster.local`**
```bash
# 포드 안에서
getent hosts backend.network-services.svc.cluster.local
getent hosts backend.network-services     # 짧은 이름도 OK
getent hosts backend                       # 같은 NS면 더 짧게
```

## 11. 🏷️ VM 서비스 상세 (라벨 전파·엔드포인트·헤드리스)
### ⚠️ 라벨 전파 함정 (시험 포인트!)
- 서비스 selector는 **virt-launcher 포드 라벨**과 매칭됨.
- VM의 여러 labels 중 **`.spec.template.metadata.labels`만 virt-launcher 포드로 전파!** (다른 labels X)
- 라벨 추가(`oc edit vm`) 후 **VM 재시작**해야 포드에 반영 (마이그레이션으론 전파 X).
- 임시 수동: `oc label pod virt-launcher-<vm>-xxxx tier=backend` → 단, **재시작하면 사라짐**(VM 리소스에도 정의 필수).
- 💡 **`virtctl expose`는 표준 라벨 `vm.kubevirt.io/name` 자동 사용** → 라벨/재시작 불필요(그래서 편함).

### 엔드포인트 검증
```bash
oc get vmi          # VMI IP (예: 10.9.0.31)
oc get endpoints    # 서비스 엔드포인트 = 그 VMI IP:targetPort (일치하면 정상)
# VM 재시작 → VMI IP 바뀜 → 엔드포인트 자동 업데이트
```

### 헤드리스(Headless) 서비스 — `clusterIP: None`
> ClusterIP 부하분산을 **우회**하고 **개별 포드/VM에 직접 연결** (분산 DB 등).
```yaml
spec:
  clusterIP: None          # ★ 헤드리스 (클러스터 IP 없음, kube-proxy 안 거침)
  selector: { tier: backend }
  ports: [ { port: 80, targetPort: 8080 } ]   # 1개 이상 필수
```
- DNS 쿼리 = 서비스 IP 대신 **연결된 포드들 IP 전부** 반환(클라이언트가 라운드로빈).
- 콘솔로 첫 VM 생성 시 `headless` 서비스 + `network.kubevirt.io/headlessService: headless` 라벨/`subdomain` **자동 생성**. (CLI 생성 VM은 수동)

## 12. 🧩 Multus CNI 플러그인 종류 + bridge NAD
| 플러그인 | 용도 |
| --- | --- |
| **bridge**(cnv-bridge) | Linux 브리지, **VM 멀티홈 필수**. 물리망 연결(외부 통신) |
| **host-device** | 물리 NIC **독점** 접근 (고처리량·저지연) |
| **ipvlan** | 호스트와 **같은 MAC, 다른 IP** (MAC 관리 단순) |
| **macvlan** | 포드/VM마다 **고유 MAC** (DHCP·모니터링 호환) |
| **SR-IOV** | SR-IOV HW 가상기능(VF) 연결 (최고 성능) |
> 🔑 **VM 멀티홈 = 보통 bridge 필요.** NAD는 **VM과 같은 네임스페이스**.

```yaml
# bridge 플러그인 NAD (cnv-bridge)
kind: NetworkAttachmentDefinition
metadata: { name: bridge-dev, namespace: multus-test }
spec:
  config: '{
    "type": "cnv-bridge",       # CNI 플러그인
    "bridge": "dev-bridge",     # 노드의 Linux 브리지 이름
    "macspoofchk": true,        # MAC 변조 방지(선택)
    "vlan": 0 }'                # VLAN 태그(선택)
```
```bash
oc get net-attach-def -n <ns>     # NAD 확인 (= oc get nad)
```
**인터페이스 이름**: VM primary(pod net)=**enp1s0**(Linux)/포드=eth0 · VM secondary=enpNsM·ethX/포드=netN → `ip address`로 확인.

## ⭐ 무조건 외울 명령 (네트워킹)
```bash
# VM 서비스 노출 (제일 자주!)
virtctl expose vm <vm> --name=<svc> --type=ClusterIP --port=80 --target-port=80
# Route 생성 (웹)
oc expose service/<svc> --name=<route>              # 평문
oc create route edge --service <svc> --hostname <host>   # 암호화(edge|passthrough|reencrypt)
# 외부 IP(LB) — non-HTTP(SSH/DB 등)
virtctl expose vm <vm> --name=<svc> --type=LoadBalancer --port=22 --target-port=22
oc get svc                 # EXTERNAL-IP 확인
oc get endpoints           # virt-launcher IP:포트 확인(<none>=selector 불일치)
nc -vz <EXTERNAL-IP> 22    # TCP 연결 검증
oc get svc,route,nad,endpoints
oc get metallb,ipaddresspool,l2advertisement -n metallb-system   # MetalLB 확인
# 2차 NIC 핫플러그 적용 = 라이브 마이그레이션
virtctl migrate <vm>
oc get nad ; oc get nncp,nnce      # NAD / NMState 정책 확인 (nad=net-attach-def)
# 검증/조회
oc get vmi ; oc get endpoints      # VMI IP ↔ 엔드포인트 일치 확인
oc get network/cluster -o yaml     # Pod/Service CIDR (관리자)
oc label pod virt-launcher-<vm>-xxxx tier=backend   # 임시 라벨(재시작 시 사라짐)
getent hosts <svc>.<ns>.svc.cluster.local           # 포드 안에서 DNS 확인
```
> 까먹으면: `virtctl expose --help` / `oc expose --help` / `oc create route --help`

## 🎯 1분 암기 체크
- [ ] Machine net(노드) / Pod net(클러스터 공용·기본) / UDN(프로젝트 전용·선택) / Service net
- [ ] **UDN 장점**: 격리 / 서브넷 재사용 / **영구 IP(NAT 없는 마이그레이션)**
- [ ] VM 기본 바인딩 = **masquerade(NAT)** / 2차 = **Multus+NAD**(bridge/SR-IOV) → 추가 후 **재부팅**
- [ ] **웹=Route / 비웹=LB·NodePort** / 온프렘 LB=**MetalLB**
- [ ] Route 전제 = **ClusterIP 서비스 먼저** → `oc expose service`
- [ ] DNS = `route-namespace.도메인` / Route 구현 = **HAProxy 라우터**
- [ ] **TLS 3종**: edge(라우터종료) / passthrough(앱) / reencrypt(전구간) → 암호화는 **`oc create route`**
- [ ] ⭐ **VM 노출 = `virtctl expose vm <vm> --name --type --port --target-port`** (라벨·재시작 자동)
- [ ] Route=OpenShift 전용(기능多) / Ingress=k8s표준(OpenShift가 route로 구현)
- [ ] **non-HTTP(SSH/DB/SMTP) = NodePort·LoadBalancer** (Route 불가) / NodePort 범위 **30000~32767**
- [ ] **LoadBalancer = 고정 IP**(노드 이동에도 유지) / 온프렘=**MetalLB**(모드 L2-ARP기본/L3-BGP)
- [ ] **MetalLB CR 3종**: MetalLB / **IPAddressPool**(IP범위) / **L2Advertisement**(`metallb-system`)
- [ ] LB 검증: `oc get svc`(EXTERNAL-IP)→`oc get endpoints`→`nc -vz`→`ssh` / endpoint `<none>`이면 selector 불일치(마이그레이션)
- [ ] `virtctl expose`는 **포트 1개만** → 여러 포트는 **YAML+name 필요**
- [ ] 멀티홈 = 2+ 네트워크 / 관리자: **NMState→NNCP(의도)·NNCE(상태·롤백)** → **NAD**(Multus가 읽음)
- [ ] NAD 토폴로지: **layer2=클러스터 내부 / localnet=외부 물리 연결**
- [ ] 2차 NIC = interface+network **name 짝** → 추가 후 **재부팅** / 핫플러그(bridge·VirtIO O, SR-IOV X)는 **라이브 마이그레이션**(`virtctl migrate`)
- [ ] 보조 NIC 정적 IP = **cloud-init `networkData`** / 동적 = 브리지 **DHCP**
- [ ] SDN 관리 = **CNO**(기본 OVN) / Multus 관리 = **CNAO**(HCO가 배포) / CIDR=`oc get network/cluster`
- [ ] DNS = **`svc.namespace.svc.cluster.local`** (짧은 이름 가능) / `getent hosts`로 확인
- [ ] ⚠️ 서비스 라벨은 **`.spec.template.metadata.labels`만** virt-launcher 포드로 전파 → 추가 후 **재시작**
- [ ] 엔드포인트 = **VMI IP:targetPort** (자동 업데이트) / `virtctl expose`는 `vm.kubevirt.io/name` 자동
- [ ] **헤드리스 = `clusterIP: None`** → 부하분산 우회, DNS가 **포드 IP들** 반환(직접 연결)
- [ ] **CNI 5종**: bridge(멀티홈 필수)/host-device/ipvlan(같은MAC)/macvlan(고유MAC)/SR-IOV / bridge type=**cnv-bridge**
- [ ] VM 인터페이스: primary=**enp1s0** / secondary=enpNsM·ethX (`ip address` 확인)
