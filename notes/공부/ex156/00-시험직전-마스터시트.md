## 1. ⭐⭐ 꼭 나오는 문제 유형 + 풀이 (오늘 시험 팁 포함)

### A. 🌐 Import (URL로 VM 가져오기) — 오늘 시험 출제!
> 문제에 import 할 **URL(http://...)** 이 주어짐. 그 주소에 **image.gz + yaml**이 있음.
```bash
# 1) URL 접속해서 보면 image.gz, yaml(매니페스트)이 있음
# 2) workstation 로그인 → scp로 yaml 파일 복사
scp <user>@<host>:/path/aaaa.yaml .
# 3) yaml 안 image url을 "문제에서 준 URL"로 치환 (DataVolume source.http.url)
#    vi aaaa.yaml → url: 부분 수정
# 4) 적용
oc apply -f aaaa.yaml
```
> 핵심: **yaml 받아서 → image url 치환 → `oc apply -f`**. (image-upload 아니라 yaml apply 패턴)

### B. 🛣️ Route(라우터) 문제 — 오늘 시험 출제!
> **8080으로 Service 생성**(pod selector = 주어진 label) → **주어진 이름으로 Route 생성**.
```bash
# Service (selector는 문제에서 준 label 사용)
oc create service clusterip <svc> --tcp=8080:8080
# → selector를 주어진 label로 맞추기 (YAML 편집 또는):
#   oc set selector svc/<svc> <label-key>=<label-value>
# Route 생성 (주어진 이름)
oc expose service <svc> --name=<route-이름>
oc get route <route-이름>             # HOST/주소 확인
```
> VM 대상이면: `virtctl expose vm <vm> --name=<svc> --port=8080 --target-port=8080` → `oc expose svc <svc> --name=<route>`

### C. ⚖️ LoadBalancer 문제 — 오늘 시험 출제!
> **80으로 Service(type=LoadBalancer) 생성**(selector = 주어진 label), **주어진 이름**.
```bash
virtctl expose vm <vm> --name=<주어진이름> --type=LoadBalancer --port=80   # target-port 생략=80
oc get svc <이름>                     # EXTERNAL-IP 확인
oc get svc <이름> -o jsonpath='{.status.loadBalancer.ingress[0].ip}'
curl http://<EXTERNAL-IP>:80          # 검증
```
> 일반 pod 대상이면 Service YAML: `type: LoadBalancer`, `selector: {주어진 label}`, `port: 80`.

### D. 🔌 Second NIC(2차 네트워크) — 오늘 시험 출제!
> **주어진 이름대로 2차 NIC 등록 → 재부팅** (SNO라 적용에 재부팅 필요).
```
콘솔: VM → Configuration → Network interfaces → Add network interface
   → Name: 주어진이름 / Network: 해당 NAD 선택 → Save
   → ★ VM 재부팅 (적용)
```

### E. 💾 스토리지 프로비저닝 + persistent — 오늘 시험 출제!
> 스토리지 프로비저닝 → **persistent로 바꾸는 메뉴 클릭** → 재부팅.
```
콘솔: VM → Configuration → Storage → Add disk (프로비저닝)
   → 디스크 ⋮ → "Make persistent" 클릭   ★핫플러그 디스크 영속화
   → ★ VM 재부팅 (적용)
```
> CLI: `virtctl addvolume <vm> --volume-name=<dv> --persist`

### F. 🥇 골든이미지 봉인 (CLI 필수)
```bash
oc get vm <vm>                        # Stopped 확인
virtctl guestfs <volume>             # PVC 열기
  virt-sysprep -a /dev/vda           # 봉인
  exit                               # 봉인 VM 시작 금지!
```

### G. 📤 Export → 아카이빙 (CLI 필수)
```bash
virtctl vmexport download <이름> --vm=<vm> --volume=<vol> --output=disk.img.gz
```

### H. 📸 스냅샷 → 변경 → 복원
```
스냅샷 생성(실행 중 OK) → 변경(touch ~/file) → VM 중지 → 복원 → 시작 → 파일 사라짐 확인
```

### I. ☁️ cloud-init (계정·SSH키·서비스)

## 2. ⭐ 무조건 외울 명령/구문 (콘솔 대체 없는 것 위주)

```bash
# 🔴 CLI 필수 2대 (콘솔 불가 — 반드시 암기)
virtctl guestfs <volume>; virt-sysprep -a /dev/vda          # 봉인
virtctl vmexport download <이름> --vm=<vm> --volume=<vol> --output=disk.img.gz   # export

# 이미지 들여오기
URL → DataVolume http source / yaml apply   (콘솔 "URL (creates PVC)")
gz  → virtctl image-upload dv <name> --size=NGi --image-path=FILE [--storage-class=SC] [--insecure]

# 복원 흐름 (gz → VM)
virtctl image-upload dv <dv> --size=10Gi --image-path=disk.img.gz
virtctl create vm --name=<vm> --volume-pvc=src:<dv> | oc apply -f -   # 한 줄로!

# 핫플러그(+영속) / 네트워크 노출
virtctl addvolume <vm> --volume-name=<dv> --persist
virtctl expose vm <vm> --name=<svc> --type=LoadBalancer --port=80
oc expose service <svc> --name=<route>

# 복제 / 스냅샷
virtctl create clone --source-name <src> --target-name <tgt> | oc apply -f -
oc get virtualmachinesnapshot ; oc get virtualmachineclone ; oc get vmexport

# 접속 / 제어 / 검증
virtctl ssh <user>@<vm>          # 키로 암호 없이
virtctl console <vm>             # 암호 필요 (Ctrl+] 로 나옴)
virtctl start|stop|restart <vm>
oc get vm,vmi,dv,pvc,svc,route,nad
```

## 3. 🔴🔴 SNO = "바꾸면 재부팅" (오늘 시험 핵심 팁!)
> **single node OpenShift라 대부분 변경이 재부팅해야 적용됨.**
- **Second NIC 추가 → 재부팅**
- **스토리지 persistent 변경 → 재부팅**
- **인스턴스 타입(리소스) 변경 → 재부팅**
- cloud-init 바꿈 → (재시작만으론 재실행 X, 재생성 필요)
> 💡 **"설정 바꿨는데 적용 안 됨" 싶으면 일단 `virtctl restart <vm>`** 하고 확인.

> 키워드 한 단어만 기억 → `--help`로 나머지 복원. (export→vmexport, 봉인→guestfs)

## 5. 🆘 오류났을 때 찾는 방법
```bash
# 리소스 상태/이벤트 (제일 먼저)
oc get vm,vmi,dv,pvc               # PHASE/STATUS 이상한 거 찾기
oc describe <리소스> <이름>        # 맨 아래 Events 섹션이 핵심!
oc get events --sort-by=.lastTimestamp   # 최근 이벤트
```
| 증상 | 원인 / 해결 |
| --- | --- |
| PVC `Pending` | **SC 이름 오타** → `oc get sc`로 정확히 / SC 확장·바인딩 확인 |
| image-upload `Waiting for PVC upload pod...` | **`--insecure`** 추가 |
| `unknown command " --xxx"` | `\` 뒤 **공백** → **한 줄로** 치기 |
| `no objects passed to apply` | 앞 명령(virtctl)이 실패 → 위 명령 먼저 고치기 |
| VM `Pending`/안 켜짐 | 노드 리소스 부족(OOM), DV 미완료 → `oc get dv` Succeeded 확인 |
| export `Pending` | **VM 실행 중** → 중지(or 스냅샷 export) |
| 설정 바꿔도 적용 안 됨 | **SNO → 재부팅** `virtctl restart <vm>` |
| 핫플러그 디스크 재시작 후 사라짐 | `--persist` 안 함 / Make persistent 안 함 |
| `virtctl ssh` 암호 물음 | SSH 공개키 주입 안 됨 (cloud-init/Public SSH key 확인) |

## 6. 🛑 "VM 중지 필요?" (헷갈림 1위)
| 작업 | VM 상태 |
| --- | --- |
| 스냅샷 **생성** / SCSI 핫플러그 / PVC 확장 | 실행 중 OK |
| 스냅샷 **복원** / **봉인(virt-sysprep)** / Export / VirtIO 디스크 | **중지 필수** |
> 디스크를 **바꾸는 일(복원·봉인·export)** = 중지 / **찍기만(스냅샷 생성)** = 실행 중.

## 7. 🎓 시험장 전술
- **지문 두 번 읽기**: VM·볼륨·네임스페이스·SC·label·이름 **그대로 복붙**. 오타가 0점 1위.
- **검증까지**: 만들면 `oc get`으로 Running/Bound/Ready 확인 + 부팅 끝까지 대기.
- **콘솔 vs CLI 자유선택**(명시 없으면 빠른 쪽). **봉인·export만 CLI 필수**, 나머지 콘솔 OK.
- **SNO = 재부팅** 습관: NIC·persistent·리소스 바꾸면 `virtctl restart`.
- **막히면 다음 문제로**, 스토리지/네트워킹 점수부터 확보.
- **SC는 문제에서 줄 때만** 명시, 안 주면 생략(default).

> **핵심 한 줄**: 스토리지 "URL=import / gz=upload" + **SNO 재부팅** + **봉인·export는 CLI** 이 세 개만 몸에 배면 합격선 넘는다. 화이팅! 💪
