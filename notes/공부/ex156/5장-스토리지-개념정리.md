## 🍱 들어가기 전: 음식점 비유 (전체 지도)

```
SC(메뉴판) → PVC(주문서) → PV(그릇)
                              ├ 비어있으면 → 빈 디스크
                              └ DataVolume이 채우면 → OS 디스크 = 부팅디스크
```

| 개념 | 비유 | 한 줄 | 범위 |
| --- | --- | --- | --- |
| **StorageClass(SC)** | 메뉴판 🗒️ | 어떤 종류 볼륨 만들 수 있나 (이름만 골라 씀) | 클러스터 |
| **PVC** | 주문서 📝 | "10Gi RWX 하나요" 요청 (내가 만드는 것) | 네임스페이스 |
| **PV** | 그릇 🍽️ | 실제로 할당된 볼륨 (보통 자동 생성) | 클러스터 |
| **DataVolume(DV)** | 그릇+음식 🍱 | PVC 만들고 + 이미지까지 채움 | 네임스페이스 |

> ⚠️ "피자(음식 담긴 그릇)가 온다" = **DataVolume으로 채웠을 때**. 그냥 PVC는 **빈 그릇(빈 PV)**만 옴. **PVC=주문서, PV=그릇**은 절대 안 바뀜.

# 5.1 가상 시스템에 퍼시스턴트 스토리지 연결

### 프로비저닝 2종 (개념)
- **정적(Static)**: 관리자가 PV를 수동으로 미리 준비 → 개발자가 PVC로 가져다 씀.
- **동적(Dynamic)**: 개발자가 PVC만 만들면 SC의 프로비저너가 **온디맨드로 PV 자동 생성**. (시험·실무 기본)

### SC = 설정 템플릿 (어떤 정보를 담나)
```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: ocs-external-storagecluster-ceph-rbd-virtualization   # 메뉴 이름
  annotations:
    storageclass.kubevirt.io/is-default-virt-class: "true"    # 가상화 기본 표시
provisioner: openshift-storage.rbd.csi.ceph.com               # 어떤 드라이버가 만드나 ★핵심
reclaimPolicy: Delete                                          # 다 쓰면 삭제/보존
allowVolumeExpansion: true                                     # 확장 가능?
volumeBindingMode: Immediate                                   # 언제 PV 만드나
```
- **provisioner** = SC의 핵심 (Ceph RBD=블록, CephFS=파일, NFS=파일...)
- 시험에선 SC를 **만들 일 거의 없음** → `oc get sc`로 **이름 확인 후 PVC에 복붙**이 99%.

**SC 기본값 주석 (구분 암기)**
- `storageclass.kubernetes.io/is-default-class=true` → **클러스터 기본** SC
- `storageclass.kubevirt.io/is-default-virt-class=true` → **가상화 전용 기본** SC
- 🔑 **둘 다 있으면 virt 주석이 우선** (VM 디스크는 virt 기본 SC 사용). 부팅 소스는 기본 SC로 생성됨.

### ⭐ 액세스 모드 (가장 잘 나옴)
| 모드 | 약어 | 의미 |
| --- | --- | --- |
| ReadWriteOnce | RWO | 한 노드 RW |
| ReadWriteOncePod | RWOP | 단일 Pod RW |
| ReadOnlyMany | ROX | 다수 읽기전용 |
| **ReadWriteMany** | **RWX** | **다수 RW** |

> 🔥 **시험 1순위 함정**: **라이브 마이그레이션 = RWX 필수.** 스냅샷·복제는 백엔드(Ceph RBD)가 지원해야.

### ⭐ 볼륨 모드
- **Filesystem** (기본) → PV에 `disk.img` 파일 생성. **요청보다 5.5% 큰 PVC** 생성.
- **Block** → 원시 블록 장치. **VM 디스크는 Block이 성능상 권장.**
> 모든 백엔드가 두 모드 다 지원하진 않음. **StorageProfile**이 SC별 최적 기본값(액세스/볼륨 모드)을 제공 → DV는 **크기만** 줘도 됨.

### 🍱 DataVolume = 디스크 제조기
> PVC만으론 **빈 디스크**뿐 → OS 없어서 VM 부팅 못 함.
> **DataVolume = PVC 만들기 + 이미지 채우기**를 한 번에. (뒤에서 **CDI** 일꾼이 처리)

```yaml
apiVersion: cdi.kubevirt.io/v1beta1
kind: DataVolume
metadata:
  name: my-vm-disk
spec:
  source:                    # ← 어디서 채울까 (4종 택1) ★시험 핵심
    http: { url: "..." }
  storage:                   # ← PVC 부분 (그릇 사양)
    storageClassName: ceph-rbd-virtualization
    resources:
      requests: { storage: 30Gi }
```

**⭐ source 4종 (꼭 구분)**
| source | 의미 | 짝꿍 작업 |
| --- | --- | --- |
| **`http:`** | URL에서 import (클러스터가 받아옴) | 콘솔 "URL (creates PVC)" |
| **`upload: {}`** | 로컬 파일 업로드 (내가 밀어넣음) | `virtctl image-upload` / 콘솔 "Upload" |
| **`pvc:`** | 기존 PVC 복제(clone) | 골든이미지 복제 |
| **`blank: {}`** | 빈 디스크 (`{}` = 빈 맵) | 추가 데이터 디스크 |

> 🔥 **URL = http / gz = upload** (제일 중요한 분기)
> **DataVolume 삭제 = PVC·PV도 같이 삭제** (단, VM에 붙어있으면 분리 후)

### 디스크 채우는 3가지 흐름 (실전)
**A. Upload — 로컬 파일 밀어넣기 (`upload` source)**
```bash
virtctl image-upload dv fedora-disk \
  --size=30Gi --image-path=fedora.img.gz \
  --storage-class=ocs-external-storagecluster-ceph-rbd-virtualization --insecure
```
- 콘솔 대체: Boot source → **"Upload"**. 함정: `Waiting for PVC upload pod...` → **`--insecure`** / `Pending` → **SC 이름 오타**

**B. URL import — 클러스터가 다운로드 (`http` source, upload의 짝)**
```
URL import → 클러스터(CDI)가 받아옴 (내가 줄 건 URL뿐)
Upload     → 내가 로컬 파일 밀어넣음 (파일이 내 손에)
```
- 콘솔: Boot source → **"URL (creates PVC)"** + URL + size + SC

**C. 골든이미지 + clone — 원본 하나로 여러 대 (`pvc` source)** → 자세히는 [5.9]
```bash
oc get pvc                          # 골든 볼륨 이름 확인
virtctl guestfs rhel-golden-volume  # 디스크 안으로 (★콘솔 불가, CLI만)
virt-sysprep -a /dev/vda            # 고유정보 제거 후
exit
```

### 노드 로컬 디스크 (참고)
- 전용 스토리지 없을 때: **hostPath / 로컬 스토리지 Operator / LVM 스토리지 Operator**로 노드 디스크 사용.
- 🔴 **노드 로컬 = 라이브 마이그레이션·스냅샷 같은 고급 기능 불가.**

### PVC 상태 읽기 + 검증
```bash
oc get sc      # 메뉴판 — 이름 확인(복붙용)
oc get dv      # PHASE: Succeeded 떠야 완료
oc get pvc     # STATUS: Bound(정상) / Pending(SC 오타 의심)
```
```
NAME  STATUS    VOLUME    CAPACITY  ACCESS  STORAGECLASS
vm1   Bound     pvc-abc   10Gi      RWX     ceph-rbd-virtualization
vm2   Pending   ...                          → PV 대기(보통 SC 이름 오타)
```

# 5.3 가상 시스템의 스토리지 장치 관리

### 🔌 디스크 인터페이스 3종 (가장 잘 나옴)
| 인터페이스 | Linux 장치명 | 핫플러그 | 특징 |
| --- | --- | --- | --- |
| **SATA** | - | ❌ | 성능 낮음, **CD-ROM**용 |
| **VirtIO** | **`/dev/vdX`** | ❌ | 최고 성능, but **PCIe 슬롯 제한** |
| **SCSI** | **`/dev/sdX`** | ✅ | virtio-scsi 컨트롤러, **핫플러그·영속화 가능** |

> 🔥 **핫플러그(실행 중 추가/제거) = SCSI만!** VirtIO는 **VM 중지** 필요.

**🆚 SCSI(`sdX`) vs VirtIO(`vdX`) — 이름으로 구분**
- VM 안에서 `lsblk` 치면 **앞글자로 인터페이스를 바로** 알 수 있음.
- **암기**: `sd`의 **s**=**S**CSI / `vd`의 **v**=**V**irtIO. 끝글자 a/b/c = 몇 번째.
- 보통 **OS 디스크=vda(VirtIO)**, 핫플러그 **데이터 디스크=sdX(SCSI)**.

> ## 🚨🚨 헷갈린 시험 지시문 — 꼭 기억! 🚨🚨
> ### "단일 기존 데이터 볼륨을 **대체할 핫 플러깅 가능 디스크**를 추가"
> **번역 → "VM을 끄지 않고(다운타임 없이) 기존 데이터 디스크를 새 디스크로 갈아끼워라"**
> - **핫 플러깅 가능 디스크 = SCSI 인터페이스** / "실행 중·다운타임 없이·핫플러그" → **무조건 SCSI**
> ```bash
> virtctl addvolume <vm> --volume-name=<새-dv>      # 실행 중 SCSI 핫플러그 추가
> virtctl removevolume <vm> --volume-name=<기존-dv> # 기존 detach
> # 영구 반영하라면 addvolume에 --persist
> ```
> **콘솔:** Configuration → Storage → Add disk → **Interface: SCSI** / 기존 ⋮ → Detach
> ⚠️ `--persist` 없으면 재시작 시 사라짐. "영구적으로/재부팅 후에도" → 무조건 persist.

### 📦 디스크 소스 (Add disk 메뉴)
| 소스 | 의미 | 영속성 |
| --- | --- | --- |
| 빈 디스크(Blank) | 포맷 안 된 원시 장치 | ✅ |
| **임시 디스크(컨테이너 이미지)** | 레지스트리 이미지, PVC/PV 안 만듦 | ❌ **재시작 시 초기화(ephemeral)** |
| 볼륨(Volume) | 기존 PVC 복사 | ✅ |
| 볼륨 스냅샷 | 스냅샷 복사 | ✅ |
| 볼륨 복제(clone) | PVC 복제본 | ✅ |

> ⚠️ **PVC 동시 마운트 금지**: 다른 VM에 연결된 PVC 동시 사용 시 ext4/XFS **파일시스템 손상**.

### 🗑️ 분리(Detach) vs 삭제(Delete)
```
Detach → 데이터는 PVC에 남음 (다른 VM 재연결 가능)
Delete → 데이터 진짜 삭제
oc delete datavolume/<name>   # DV 삭제 → PVC·PV도 같이 제거
```

### 💾 사전 할당 (Preallocation)
- 기본: 쓴 만큼만 할당(thin) / **`preallocation: true`**: 전체 미리 예약(0으로 채움, 쓰기 빠름)
```yaml
spec:
  preallocation: true
  source: { blank: {} }
```
> 콘솔: Add disk → **Enable preallocation** 체크. (보고 크기는 둘 다 동일)

### 📏 ⭐ 디스크 크기 조정 (Resize) — **PVC는 확장만, 축소 불가!**
```
1. SC가 확장 지원?  → oc get sc <sc> -o yaml | grep allowVolumeExpansion  (true여야 함)
2. PVC 확장         → 콘솔 Expand PVC / oc edit pvc (spec.resources.requests.storage ↑)
3. VM 안에서 FS 확장 → 재시작 후 OS 툴로 파티션·파일시스템 확장 (cloud-init 있으면 자동)
```
> 🔑 PVC 확장은 **VM 중지 불필요**(실행 중 가능), 단 **재시작해야 새 크기 인식**. 파티션·FS는 자동 확장 안 됨.

**🖥️ VM 안에서 FS 확장 명령 (3단계 중 ③)**
```bash
lsblk                       # 디스크/파티션 크기 확인 (커졌나?)
df -h /dev/sda              # 파일시스템 실제 용량/사용률 확인
sudo xfs_growfs /dev/sda    # XFS를 디스크 끝까지 확장 (ext4면 resize2fs)
```
> 흐름: **`lsblk`(디스크 커짐 확인) → `xfs_growfs`(FS 확장) → `df -h`(검증)**.
> **XFS=`xfs_growfs` / ext4=`resize2fs`** (뒤에 장치명만). 이름이 직관적(grow filesystem)이라 가볍게 암기.

**📸 실전 화면 — "디스크는 컸는데 FS가 안 큰" 상태 (시험 단골!)**
```
$ lsblk
sda  10G disk /mariadb/data   ← SCSI 데이터, 10G로 확장됨
vda  10G disk                 ← VirtIO OS 디스크
├─vda2 200M part /boot/efi    ← part=파티션 조각
├─vda3 600M part /boot
└─vda4 9.2G part /            ← 루트
$ df -h /dev/sda
/dev/sda  5.0G ... /mariadb/data   ← FS는 아직 5.0G!
```
> 🔥 `lsblk` 10G vs `df` 5.0G → 디스크는 컸지만 FS 안 따라옴 → **`xfs_growfs`만 하면 완성.**

# 5.5 가상 시스템 내보내기 및 가져오기

> 한 클러스터의 VM(정의+디스크)을 **다른 클러스터로 이사**시키기. (CR: `VirtualMachineExport`)

### 내보내기(Export)
```bash
# 1) export 생성
virtctl vmexport create --vm=fedora-vm fedora-export
oc get vmexport                      # PHASE: Ready 확인
oc describe vmexport/fedora-export   # 다운로드 링크/토큰 확인

# 2) 매니페스트 번들 다운로드 (다른 클러스터로 가져갈 설정 묶음)
virtctl vmexport download fedora-export --keep-vme --manifest --include-secret --output fedora-vm.yml

# 3) 볼륨(디스크) 다운로드
virtctl vmexport download fedora-export --keep-vme --volume fedora-vm --output disk.img.gz

# 4) 정리
virtctl vmexport delete fedora-export
```
| 플래그 | 의미 |
| --- | --- |
| `--keep-vme` | 다운로드 후 **VME 자동삭제 막기**(유지) |
| `--manifest` / `--volume` | 매니페스트 번들 / 디스크 받기 |
| `--include-secret` | 번들에 **export 토큰 시크릿 포함** |
| `--output` | 저장 파일명 |

- **포맷 2종**: `raw`(원본) / `gzip`(압축, `.img.gz`)
- **ttlDuration**: export 자동삭제 시간, **미지정 시 기본 2시간**. 링크는 **토큰**으로 보호.
- 매니페스트 번들 = VM 정의 + **CA 인증서 ConfigMap** + **export 토큰 Secret** + DataVolume(http source).
- 🔴 **데이터 일관성 위해 export 전 VM 중지**. 실행 중이면 export **Pending**.
  → 끄기 싫으면 **스냅샷을 export**: `virtctl vmexport create --snapshot=<snap> <export>`

### 가져오기(Import)
```bash
oc apply -f fedora-vm.yml     # 매니페스트 번들 적용 → 타겟이 소스에서 디스크 받아옴
```
- ⚠️ **소스와 동일 네임스페이스로 들어옴 → 타겟에 그 NS 미리 생성 필요.**
- VM 정의 가져오기는 **OpenShift Virt ↔ OpenShift Virt 간만**. 타 하이퍼바이저는 **MTV(마이그레이션 툴킷)**.
- 디스크 이미지만(ISO/raw/qcow2): `virtctl image-upload dv` → `virtctl create vm --volume-pvc src:<dv> | oc apply -f -`

# 5.7 가상 시스템 스냅샷 관리

> 특정 시점 VM 상태(디스크+구성) 저장 → 문제 생기면 되돌리기.

```bash
oc get virtualmachinesnapshot          # 목록 (READYTOUSE: true)
oc delete virtualmachinesnapshot <이름> # 삭제 (VM 중지 불필요)
```
```yaml
# 생성 (콘솔: Snapshots 탭 → Take snapshot)
kind: VirtualMachineSnapshot
spec:
  source: { apiGroup: kubevirt.io, kind: VirtualMachine, name: mariadb-server }
---
# 복원 (콘솔: Snapshots → ⋮ → Restore)
kind: VirtualMachineRestore
spec:
  target: { apiGroup: kubevirt.io, kind: VirtualMachine, name: mariadb-server }
  virtualMachineSnapshotName: mariadb-server-20250905
```
**꼭 알 것**
- **QEMU 게스트 에이전트** 있으면 → 실행 중 스냅샷 시 **파일시스템 freeze**로 일관성. 없어도 라이브 스냅샷 되나 **불일치 위험**. (Red Hat 기본 템플릿엔 포함)
- **CSI 드라이버가 스냅샷 지원**해야. 미지원 디스크는 경고 + **복원해도 그 디스크는 안 돌아감**.
- 스냅샷은 **구성(CPU/메모리·디스크 구성)도 기록** → 복원 시 원래 구성으로.
- 🔴 **복원하려면 VM 중지 먼저!** (생성은 실행 중 가능, 복원은 중지 필수)
- 스냅샷=Kubernetes **VolumeSnapshot**(디스크당 1개, `oc get volumesnapshots`). 개별 디스크만 새 PVC로 복원해 붙일 수도(Add disk → Volume snapshot).

**생명주기 / 정리**
- 생성: 콘솔 Take snapshot, 또는 CLI `oc apply -f snapshot.yaml`.
- 🔁 스냅샷 **생성 전 VM을 중지했다면 → 생성 후 다시 시작**. (게스트에이전트 없을 때 일관성 위해 중지하는 패턴)
- 스냅샷으로 **VM 복사본/복제본 생성** 가능(Snapshots → ⋮ → Create VirtualMachine).
- 스냅샷은 **백엔드 디스크 공간 사용** → 안 쓰는 건 삭제. `oc delete virtualmachinesnapshot <이름>` (VM 중지 불필요).

> ## ⭐ 복원 시 "디스크 구성 변경" 동작 (헷갈림 주의)
> **복원 = 스냅샷 찍던 그 순간의 디스크 구성으로 리셋.** 스냅샷 이후 바꾼 구성은 되돌려짐.
>
> **① 스냅샷 후 디스크를 제거했었다 → 복원하면 다시 생김**
> - 그 디스크가 **스냅샷 지원 SC** → 볼륨 스냅샷에서 **데이터까지 복원** ✅
> - **스냅샷 미지원 SC**(예: nfs) → **빈 디스크(같은 크기·특성)**로만 재생성 → **데이터 손실** ❌ (스냅샷 전/후 둘 다 안 돌아옴)
>
> **② 스냅샷 후 디스크를 추가했었다 → 복원하면 그 디스크 제거됨** (스냅샷엔 없던 디스크라서)
>
> 💡 교훈: 스냅샷 찍고 디스크 구성 바꿨으면, 복원 전 "이 변경이 날아간다" 인지 + 필요 데이터 백업.

> ✍️ **복원 검증 패턴**: 스냅샷 → 파일 변경/삭제 → 복원 → 파일 원상복구 확인. 지문에서 "스냅샷 **전/후**" 순서 두 번 읽기(채점은 파일 존재로).

# 5.9 가상 시스템 복제

> 모델 VM 하나 잘 만들어 → 여러 대 복제. 단 **봉인(seal)** 먼저!

### 왜 봉인(sealing)?
복제본이 원본과 **같은 고유정보(MAC, 정적IP, SSH 호스트키·인증서, 머신ID, 로그, Windows SID)**를 가지면 충돌 → 복제 전 제거.
- **Windows**: `sysprep.exe` (OOBE) / **RHEL**: `virt-sysprep`
- `virt-sysprep`은 **VM 내부가 아니라 디스크 블록장치에서** 실행 → **VM 중지 필수**

```bash
# guestfs 컨테이너로 PVC 열기 (libguestfs-tools, PVC를 /dev/vda로 마운트)
virtctl guestfs -n golden-vms dsk1
  virt-sysprep --list-operations   # 가능한 봉인 작업 40+종
  virt-sysprep -a /dev/vda         # 전체 봉인
  virt-sysprep -a /dev/vda --enable ca-certificates,user-account --remove-user-accounts cloud-user
  exit
```
- 🔴 **봉인한 VM은 시작 금지!** 부팅하면 OS가 지운 정보 재생성 → 다시 봉인해야 함.
- guestfs는 **PVC 1개만** 대화형 연결. 동시 편집 금지(손상 위험).
- guestfs 안 다른 툴: `virt-edit`(파일 편집), `virt-customize`(SSH키 주입·패키지), `guestfish`(대화형 셸).
- 💡 봉인 복제 대신 **봉인된 부팅소스 템플릿 + cloud-init/Ansible**로 새 VM 구성도 가능.

### 복제 방법
```bash
# 콘솔: VM 중지 → Actions → Clone
# CLI 전체 VM 복제 (CR: VirtualMachineClone)
virtctl create clone --source-name golden-vm --target-name new-vm | oc apply -f -
```
```yaml
# 개별 디스크 복제 (DataVolume, source: pvc)
kind: DataVolume
spec:
  source:
    pvc: { name: documentroot, namespace: golden-vms }
  storage:
    resources: { requests: { storage: 1Gi } }   # 소스 PVC와 같거나 커야
    storageClassName: ocs-external-storagecluster-ceph-rbd-virtualization
```
- 소스 VM 실행 중이면 DV가 **CloneInProgress** → **VM 중지하면 완료(Succeeded)**.

### 복제 전략 (cloneStrategy, StorageProfile에 지정)
| 전략 | 별칭 | 방식 | 속도 |
| --- | --- | --- | --- |
| **csi-clone** | CSI 볼륨 복제 | 백엔드 복제 기능 | 빠름 |
| **snapshot** | 스마트 복제 | 백엔드 스냅샷 기능 | 빠름 |
| **copy** | 호스트 지원 복제 | Pod로 직접 복사 | **느림** |
> CSI/스마트 복제는 소스·타겟 **SC와 볼륨모드 같아야**, 소스 볼륨 **미사용**. 미지정 시 스냅샷 우선, 안 되면 copy.

> 💡 **DV 자동삭제 규칙**: VM 만들 때 생긴 DV → VM 삭제 시 **같이 삭제**. **따로 만든 DV는 자동삭제 안 됨**(재사용 가능).
