# 5장 스토리지 개념정리 (초보자용 · 비유 중심)

> EX156 약점 영역(33%) 기초 다지기. **개념부터** 쌓는 노트.
> 핵심 한 줄: **SC=메뉴판 / PVC=주문서 / PV=그릇 / DataVolume=그릇 채워서 주문**

---

## 0. 🍱 음식점 비유 (전체 지도)

```
SC(메뉴판) → PVC(주문서) → PV(그릇)
                              ├ 비어있으면 → 빈 디스크
                              └ DataVolume이 채우면 → OS 디스크 = 부팅디스크
```

| 개념 | 비유 | 한 줄 | 범위 |
| --- | --- | --- | --- |
| **StorageClass(SC)** | 메뉴판 🗒️ | 어떤 종류 볼륨 만들 수 있나 (이름만 골라 씀) | 클러스터 |
| **PVC** | 주문서 📝 | "10Gi RWX 하나요" 요청 (내가 만드는 것) | 네임스페이스 |
| **PV** | 그릇 🍽️ | 실제로 할당된 볼륨 (보통 자동 생성) | 클러스터 |
| **DataVolume(DV)** | 그릇+음식 🍱 | PVC 만들고 + 이미지까지 채움 | 네임스페이스 |

> ⚠️ **헷갈림 주의**: "피자(음식 담긴 그릇)가 온다" = **DataVolume으로 채웠을 때**.
> 그냥 PVC로 주문하면 **빈 그릇(빈 PV)**만 옴.
> **PVC=주문서, PV=그릇**은 절대 안 바뀜.

## 1. SC = 설정 템플릿 (어떤 정보를 담나)

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: ocs-external-storagecluster-ceph-rbd-virtualization   # 메뉴 이름
  annotations:
    storageclass.kubevirt.io/is-default-virt-class: "true"    # 가상화 기본 표시
provisioner: openshift-storage.rbd.csi.ceph.com               # 어떤 드라이버가 만드나 ★핵심
reclaimPolicy: Delete                                          # 다 쓰면 삭제/보존
allowVolumeExpansion: true                                     # 확장 가능?
volumeBindingMode: Immediate                                   # 언제 PV 만드나
```

- **provisioner** = SC의 핵심 (Ceph RBD=블록, CephFS=파일, NFS=파일...)
- 시험에선 SC를 **만들 일 거의 없음** → `oc get sc`로 **이름 확인 후 PVC에 복붙**이 99%.

### SC 기본값 주석 (구분 암기)
- `storageclass.kubernetes.io/is-default-class=true` → **클러스터 기본** SC
- `storageclass.kubevirt.io/is-default-virt-class=true` → **가상화 전용 기본** SC
- 🔑 **둘 다 있으면 virt 주석이 우선** (VM 디스크는 virt 기본 SC 사용)

## 2. ⭐ 액세스 모드 (가장 잘 나옴)

| 모드 | 약어 | 의미 |
| --- | --- | --- |
| ReadWriteOnce | RWO | 한 노드 RW |
| ReadWriteOncePod | RWOP | 단일 Pod RW |
| ReadOnlyMany | ROX | 다수 읽기전용 |
| **ReadWriteMany** | **RWX** | **다수 RW** |

> 🔥 **시험 1순위 함정**: **라이브 마이그레이션 = RWX 필수.** 스냅샷·복제도 백엔드(Ceph RBD) 필요.

## 3. ⭐ 볼륨 모드

- **Filesystem** (기본) → PV에 `disk.img` 파일 생성. **요청보다 5.5% 큰 PVC** 생성.
- **Block** → 원시 블록 장치. **VM 디스크는 Block이 성능상 권장.**

## 4. 🍱 DataVolume = 디스크 제조기

> PVC만으론 **빈 디스크**뿐 → OS 없어서 VM 부팅 못 함.
> **DataVolume = PVC 만들기 + 이미지 채우기**를 한 번에. (뒤에서 **CDI** 일꾼이 채움)

```yaml
apiVersion: cdi.kubevirt.io/v1beta1
kind: DataVolume
metadata:
  name: my-vm-disk
spec:
  source:                    # ← 어디서 채울까 (4종 택1) ★시험 핵심
    http: { url: "..." }
  storage:                   # ← PVC 부분 (그릇 사양)
    storageClassName: ceph-rbd-virtualization
    resources:
      requests:
        storage: 30Gi
```

### ⭐ source 4종 (꼭 구분)

| source | 의미 | 짝꿍 작업 |
| --- | --- | --- |
| **`http:`** | URL에서 import (클러스터가 받아옴) | 콘솔 "URL (creates PVC)" |
| **`upload: {}`** | 로컬 파일 업로드 (내가 밀어넣음) | `virtctl image-upload` / 콘솔 "Upload" |
| **`pvc:`** | 기존 PVC 복제(clone) | 골든이미지 복제 |
| **`blank: {}`** | 빈 디스크 (`{}` = 빈 맵) | 추가 데이터 디스크 |

> 🔥 **URL = http / gz = upload** (제일 중요한 분기)
> **DataVolume 삭제 = PVC·PV도 같이 삭제** (단, VM에 붙어있으면 분리 후)
> **StorageProfile** 덕에 DV는 **크기만** 줘도 액세스/볼륨 모드 자동.

## 5. 디스크 채우는 3가지 흐름 (실전)

### A. Upload — 로컬 파일 밀어넣기 (`upload` source)
```bash
virtctl image-upload dv fedora-disk \
  --size=30Gi \
  --image-path=fedora.img.gz \
  --storage-class=ocs-external-storagecluster-ceph-rbd-virtualization \
  --insecure
```
- 콘솔 대체 가능: Boot source → **"Upload (Upload a new file to a PVC)"**
- 함정: `Waiting for PVC upload pod...` 멈춤 → **`--insecure`** / `Pending` → **SC 이름 오타**

### B. URL import — 클러스터가 다운로드 (`http` source, upload의 짝)
```
URL import → 클러스터(CDI)가 받아옴 (내가 줄 건 URL뿐)
Upload     → 내가 로컬 파일 밀어넣음 (파일이 내 손에)
```
- 콘솔: Boot source → **"URL (creates PVC)"** + URL + size + SC
```yaml
spec:
  source:
    http:
      url: "https://content.example.com/rhel9.qcow2"
```

### C. 골든이미지 + clone — 원본 하나로 여러 대 (`pvc` source)
```
원본 디스크 → guestfs+virt-sysprep로 청소 → 골든이미지
   → clone(pvc source)으로 새 VM 여러 대 찍어내기
```
**왜 청소?** 그대로 복제하면 머신ID·SSH키·IP 흔적이 같아 충돌 → `virt-sysprep`로 제거.
```bash
# VM은 반드시 stop 상태!
oc get pvc                          # 골든 볼륨 이름 확인
virtctl guestfs rhel-golden-volume  # 디스크 안으로 (★콘솔 불가, CLI만)
virt-sysprep -a /dev/vda            # 고유정보 제거
exit
```
- clone 콘솔: VM → **Actions → Clone**, 또는 Boot source → **"PVC (clone PVC)"**
```yaml
spec:
  source:
    pvc:
      namespace: golden-ns
      name: rhel-golden-volume
```

## 7. 콘솔 vs CLI 전략 (합격선 210/300)

> **콘솔 메인 + CLI 5개 안전장치**. 콘솔만으론 합격 보장 안 됨.

| 작업 | 콘솔 | CLI |
| --- | --- | --- |
| VM 생성/시작/정지, 스냅샷/복원/복제, 핫플러그, URL/Upload | ✅ | ✅ |
| **골든이미지 (guestfs+virt-sysprep)** | ❌ 불가 | ✅ **필수** |
| **볼륨 내보내기 다운로드 (vmexport download)** | ❌ 사실상 불가 | ✅ **필수** |

```bash
# 콘솔 불가 → 반드시 CLI로 연습할 것
virtctl guestfs <pvc> ; virt-sysprep -a /dev/vda           # 골든이미지
virtctl vmexport download <name> --vm=<vm> --volume=<vol> --output=disk.img.gz
virtctl console <vm>                                        # 검증
oc get vm,vmi,dv,pvc                                        # 검증
```

- 시험은 **docs 열람 가능** → 플래그 토씨 암기 X, **흐름만** 이해.
- `image-upload`는 **콘솔 Upload로 대체 가능** → 안 외워도 됨.

## 8. 디스크 장치 관리 (2세션 — 만든 디스크 붙이기/빼기/키우기)

### 🔌 디스크 인터페이스 3종 (가장 잘 나옴)
| 인터페이스 | Linux 장치명 | 핫플러그 | 특징 |
| --- | --- | --- | --- |
| **SATA** | - | ❌ | 성능 낮음, **CD-ROM**용 |
| **VirtIO** | **`/dev/vdX`** | ❌ | 최고 성능, but **PCIe 슬롯 제한** |
| **SCSI** | **`/dev/sdX`** | ✅ | virtio-scsi 컨트롤러, **핫플러그·영속화 가능** |

> 🔥 **핫플러그(실행 중 추가/제거) = SCSI만!** VirtIO는 **VM 중지** 필요. 장치명 vdX/sdX 구분.

#### 🆚 SCSI(`sdX`) vs VirtIO(`vdX`) — 장치 이름이 왜 갈리나
- VM 안에서 `lsblk` 치면 디스크 이름 앞글자로 **인터페이스를 바로 알 수 있어요.**

| 이름 | 인터페이스 | 의미 | 핫플러그 |
| --- | --- | --- | --- |
| **`sda`, `sdb`, `sdc`...** | **SCSI** | `sd`=SCSI 디스크 (a→b→c 순서) | ✅ 가능 (주로 **데이터 디스크**) |
| **`vda`, `vdb`...** | **VirtIO** | `vd`=VirtIO 디스크 | ❌ (주로 **OS/부팅 디스크**) |

> **암기**: `sd`의 **s** = **S**CSI / `vd`의 **v** = **V**irtIO. 앞글자만 보면 끝.
> 끝글자 a/b/c = 몇 번째 디스크 (sda=SCSI 1번, sdb=2번...).
> 보통 **OS 디스크는 vda(VirtIO)**, 핫플러그로 붙이는 **데이터 디스크는 sdX(SCSI)** 로 깔려요.

> ## 🚨🚨 헷갈린 시험 지시문 — 꼭 기억! 🚨🚨
> ### "단일 기존 데이터 볼륨을 **대체할 핫 플러깅 가능 디스크**를 추가"
> **번역하면 → "VM을 끄지 않고(다운타임 없이) 기존 데이터 디스크를 새 디스크로 갈아끼워라"**
>
> - **핫 플러깅 가능 디스크 = SCSI 인터페이스** (이게 핵심!)
> - "실행 중 / 다운타임 없이 / 핫플러그" 단어 보이면 → **무조건 SCSI 선택** (VirtIO 고르면 VM 꺼야 해서 오답)
>
> **작업 흐름:**
> ```bash
> virtctl addvolume <vm> --volume-name=<새-dv>      # 실행 중 VM에 SCSI로 핫플러그 추가
> virtctl removevolume <vm> --volume-name=<기존-dv> # 기존 볼륨 분리(detach)
> # 영구 반영하라면 → addvolume 시 --persist 추가
> ```
> **콘솔:** VM → Configuration → Storage → Add disk → **Interface: SCSI** / 기존 디스크 ⋮ → Detach
>
> ⚠️ `--persist` 없이 붙이면 재시작 시 사라짐. "영구적으로/재부팅 후에도" 있으면 무조건 persist.

### 📦 디스크 소스 (Add disk 메뉴)
| 소스 | 의미 | 영속성 |
| --- | --- | --- |
| 빈 디스크(Blank) | 포맷 안 된 원시 장치 | ✅ |
| **임시 디스크(컨테이너 이미지)** | 레지스트리 이미지, PVC/PV 안 만듦 | ❌ **재시작 시 초기화(ephemeral)** |
| 볼륨(Volume) | 기존 PVC 복사 | ✅ |
| 볼륨 스냅샷 | 스냅샷 복사 | ✅ |
| 볼륨 복제(clone) | PVC 복제본 | ✅ |

> ⚠️ **PVC 동시 마운트 금지**: 다른 VM에 연결된 PVC 동시 사용 시 ext4/XFS **파일시스템 손상**. clone 시 소스 VM/Pod 중지.

### 🗑️ 분리(Detach) vs 삭제(Delete)
```
Detach → 데이터는 PVC에 남음 (다른 VM 재연결 가능)
Delete → 데이터 진짜 삭제
oc delete datavolume/<name>   # DV 삭제 → PVC·PV도 같이 제거
```

### 💾 사전 할당 (Preallocation)
- 기본: 쓴 만큼만 할당(thin) / **preallocation: true**: 전체 미리 예약(쓰기 빠름)
```yaml
spec:
  preallocation: true
  source: { blank: {} }
```
> 콘솔: Add disk → **Enable preallocation** 체크.

### 📏 ⭐ 디스크 크기 조정 (Resize) — **PVC는 확장만, 축소 불가!**
**3단계로 기억:**
```
1. SC가 확장 지원?  → oc get sc <sc> -o yaml | grep allowVolumeExpansion  (true여야 함)
2. PVC 확장         → 콘솔 Expand PVC / oc edit pvc (spec.resources.requests.storage ↑)
3. VM 안에서 FS 확장 → 재시작 후 OS 툴로 파티션·파일시스템 확장 (cloud-init 있으면 자동)
```
> 🔑 PVC 확장은 **VM 중지 불필요**(실행 중 가능), 단 **재시작해야 새 크기 인식**. OS가 크기는 봐도 파티션·FS는 **자동 확장 안 됨**.

#### 🖥️ VM 안에서 FS 확장하는 실제 명령 (3단계 중 ③)
```bash
lsblk                       # 디스크/파티션 목록과 크기 확인 (새 크기 반영됐나?)
df -h /dev/sda              # 마운트된 파일시스템의 실제 사용량/용량 확인 (확장 전 크기)
sudo xfs_growfs /dev/sda    # XFS 파일시스템을 디스크 끝까지 확장 (실제 확장 작업)
```
| 명령 | 하는 일 |
| --- | --- |
| `lsblk` | 블록 장치(디스크·파티션) 트리와 크기 표시 → **디스크가 커졌는지** 먼저 확인 |
| `df -h /dev/sda` | 해당 장치의 **파일시스템 용량/사용률**을 사람이 읽기 쉽게(-h) 표시 |
| `sudo xfs_growfs /dev/sda` | **XFS** 파일시스템을 늘어난 디스크 크기에 맞춰 확장 (ext4면 `resize2fs`) |

> 흐름: **`lsblk`로 디스크 커진 것 확인 → `xfs_growfs`로 FS 확장 → `df -h`로 늘어난 용량 검증.**
> 디스크는 커졌는데 `df -h`가 그대로면 → FS 확장(`xfs_growfs`)을 아직 안 한 것.
> 파일시스템 종류 주의: **XFS → `xfs_growfs`**, **ext4 → `resize2fs`**.

##### ❓ `sudo xfs_growfs /dev/sda` 외워야 하나?
- **가볍게 외워두는 게 좋아요.** 이건 일반 RHEL 명령이라 **OpenShift docs에서 빨리 안 나와요.** (docs는 OCP 위주)
- 다행히 **이름이 직관적**: **`xfs` + `growfs`(grow filesystem = FS 키우기)**. → "XFS를 키운다" 그대로.
- 짝만 같이: **XFS=`xfs_growfs`**, **ext4=`resize2fs`**. 둘 다 **뒤에 장치명**(`/dev/sda`)만 붙이면 끝.
- 외우는 부담 ↓: `df -h`로 종류 파악 → "grow시킨다" 한 단어만 떠올리면 복원 가능.

#### 📸 실전 화면 예시 — "디스크는 컸는데 FS가 안 큰" 상태 (시험 단골!)
```
$ lsblk
NAME   SIZE TYPE MOUNTPOINTS
sda     10G disk /mariadb/data      ← SCSI 디스크(데이터), 10G로 확장됨
sdb      5G disk /mariadb/redo      ← SCSI 디스크
sdc      5G disk /mariadb/undo      ← SCSI 디스크
vda     10G disk                    ← VirtIO 디스크(OS)
├─vda1   1M part                    ← 파티션(part) = vda를 쪼갠 조각
├─vda2 200M part /boot/efi
├─vda3 600M part /boot
└─vda4 9.2G part /                  ← 루트(/)

$ df -h /dev/sda
Filesystem  Size  Used Avail Use% Mounted on
/dev/sda    5.0G  119M  4.9G   3% /mariadb/data   ← FS는 아직 5.0G!
```
> 🔥 **핵심 단서**: `lsblk`의 sda=**10G** vs `df -h`의 sda=**5.0G** → **디스크는 확장됐지만 FS가 안 따라옴.**
> → **PVC 확장+재시작은 됐고, `sudo xfs_growfs /dev/sda`만 하면 5.0G→10G 완성.**
>
> - `sd*`=SCSI(데이터 디스크 3종), `vd*`=VirtIO(OS 디스크)
> - `vda1~4`=`vda`를 나눈 **파티션**(efi/boot/root) / TYPE: **disk=통째, part=조각**

## 🎯 1분 암기 체크
- [ ] SC=고르는 것 / PVC=내가 만드는 것 / PV=자동 생기는 것 / DV=채워서 줌
- [ ] **피자(채워진 디스크) = DataVolume** 일 때만 옴
- [ ] **source 4종**: http(URL)/upload(로컬)/pvc(복제)/blank(빈)
- [ ] **URL=http / gz=upload**
- [ ] **RWX = 라이브 마이그레이션** (제일 중요)
- [ ] VM 디스크 = **Block 모드** 권장, Filesystem은 5.5% 큼
- [ ] virt 기본 SC 주석이 클러스터 기본보다 **우선**
- [ ] `oc get dv` → **Succeeded** / `oc get pvc` → **Bound**
- [ ] DV 삭제 → PVC·PV 같이 삭제
- [ ] **골든이미지·export 다운로드 = CLI 필수** (콘솔 불가)
- [ ] 🚨 **핫플러그(실행 중 추가/교체) = SCSI만** / VirtIO는 VM 중지
- [ ] 장치명 **`sd`=SCSI / `vd`=VirtIO** (앞글자!), 끝글자 a/b/c=몇 번째
- [ ] 임시 디스크(컨테이너) = 재시작 시 초기화 / Detach ≠ Delete
- [ ] **PVC는 확장만, 축소 X** → SC 확장지원 확인 → PVC 확장 → 재시작 후 OS에서 FS 확장
- [ ] FS 확장: **XFS=`xfs_growfs`**, ext4=`resize2fs` (뒤에 장치명) / `lsblk`>`df`면 아직 안 함
