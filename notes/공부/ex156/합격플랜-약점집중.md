## ★ 0. 어제 시험에서 실제로 나온 것 (복기)

## ★ 1. VM 생성 — "부팅 디스크를 어디서 가져오나" (점수 갈리는 분기)

> VM을 새로 만들 때 **부팅 소스(Boot source)**를 골라야 한다. **문제가 주는 게 원격 URL이냐 / 로컬 gz 파일이냐**로 방법이 갈린다.

### 콘솔 Boot source 4종 (VM 생성 마법사에서 선택)
| 문제가 주는 것 | 콘솔 Boot source | 뒤에서 일어나는 일 |
|---|---|---|
| **원격 URL** (`https://.../x.qcow2`) | **"URL (creates PVC)"** | CDI가 **다운로드(import)** |
| **로컬 파일** (`.img.gz`/`.qcow2`/`.iso`) | **"Upload"** | 내가 **업로드** |
| 기존 PVC/볼륨 | **"PVC (clone PVC)"** | 복제(clone) |
| 컨테이너 이미지 | **"Registry"** | 컨테이너 디스크 |

### ⭐ 핵심 분기 = URL vs gz (이 한 줄)
> **URL = Import = 클러스터(CDI)가 받아옴** / **gz = Upload = 내가 밀어넣음**

### ✅ 콘솔로 하면 (제일 빠름, 추천)
```
VM 생성 마법사 → Boot source 선택
   • URL이면  → "URL (creates PVC)" → URL 붙여넣기
   • gz이면   → "Upload" → 로컬 파일 선택
 → Disk size + Storage class 지정 → Create
```
> 💡 **둘 다 콘솔로 끝남.** (그래서 image-upload CLI는 안 외워도 됨)

### 🖥️ CLI로 하면
```bash
# gz(로컬) → image-upload (SC는 문제에서 줄 때만)
virtctl image-upload dv fedora-rootdisk --size=30Gi --image-path=fedora-vm-disk.img.gz [--insecure]
oc get dv,pvc                         # Succeeded / Bound 확인
# → 이 PVC로 VM 생성
virtctl create vm --name=<vm> --volume-pvc=src:fedora-rootdisk | oc apply -f -
```
```yaml
# URL(원격) → DataVolume YAML (source.http.url)
spec:
  source:
    http: { url: "https://content.example.com/rhel9.qcow2" }   # 문제가 준 URL
  storage:
    resources: { requests: { storage: 30Gi } }
```
> 함정: 업로드가 `Waiting for PVC upload pod...`에서 멈추면 → **`--insecure`** / PVC가 `Pending`이면 → **SC 이름 오타**(`oc get sc` 확인).

## ★ 2. 스토리지 집중 (33% → 목표 80%+) — 시간의 절반 투자

### 2-1. 객체 관계 (이 그림을 머리에)
```
StorageClass ──► PVC ◄── DataVolume(DV) ──(CDI)── import / upload / clone
                  │
                  └─► VM disk
```
- **DataVolume(DV)** = PVC를 만들고 내용을 채우는(import/upload/clone) 상위 객체
- **accessModes**: `RWO`/`RWX` — 라이브 마이그레이션·일부 작업은 **RWX 필요**
- **volumeMode**: `Filesystem` vs `Block`

### 2-2. 골든 이미지 (sysprep) — 어제 출제됨
> **VM은 반드시 stop 상태**여야 PVC를 guestfs로 열 수 있다.
```bash
oc get pvc                          # 1) 골든 볼륨 이름 확인
virtctl guestfs rhel-golden-volume  # 2) PVC를 마운트해 셸 진입
virt-sysprep -a /dev/vda            # 3) 머신ID·SSH키·로그 제거(일반화)
exit                                # 4) 빠져나오면 깨끗한 골든 이미지
```
- 디스크 경로 확인: guestfs 안에서 `virt-filesystems -a /dev/vda` 또는 `lsblk`
- `virt-sysprep` = "복제 템플릿용으로 디스크 청소" (복제 VM마다 고유 ID 생성되게)

### 2-3. 스냅샷 / 클론 / 복원 — 어제 출제됨
| 작업 | 위치 | 핵심 |
|---|---|---|
| **클론** | 콘솔 | VM → Actions → Clone (새 복사본) |
| **스냅샷 생성** | 콘솔 | VM → Snapshots → Take snapshot (**오프라인이 안전**) |
| **복원** | 콘솔+CLI | **VM 중지 후** Restore / CLI는 `VirtualMachineRestore` CR |

**복원 검증용 파일 패턴 — 지문 순서를 정확히:**
```bash
# 시나리오: 스냅샷 → 변경 → 복원하면 변경이 사라져야 함
touch update_failed.txt   # 빈 파일을 "미리" 만들라고 하면 순서 주의
```
> ⚠️ 함정: "스냅샷 **전에** 만들 파일"인지 "복원 **후에** 있어야/없어야 할 파일"인지 **지문 두 번 읽기**. 채점은 파일 존재 여부로 판정.

### 2-4. 내보내기(Export) / 다운로드 — 어제 출제됨
```bash
# 볼륨을 gz로 내려받기 (export 생성 + 다운로드 한 번에)
virtctl vmexport download dev-server \
  --vm=dev-server \
  --volume=dev-server-volume \
  --output=dev-server-disk.img.gz

# 이미 만들어진 export 이름으로 다운로드만
virtctl vmexport download <EXPORT_NAME> --output=disk.img.gz
```
- 첫 인자 = **새로 만들 VirtualMachineExport 이름** (VM 이름과 같아도 됨 — 헷갈리지 말 것)
- 소스 플래그: `--vm=` / `--pvc=` / `--snapshot=` 중 하나
- 기본 포맷 gzip → 보통 `--output`만 주면 됨

### 2-5. 아카이브 디스크 → 새 볼륨 → 새 VM (이관/복원 묶음 출제)
```bash
# 받아둔 gz를 새 DataVolume으로 업로드 후 → VM 생성
virtctl image-upload dv dev-server-restored-disk \
  --size=10Gi \
  --image-path=dev-server-disk.img.gz \
  --insecure
```
> **한 줄 흐름**: `vmexport download(gz로 빼냄)` → `image-upload(새 DV로 넣음)` → VM 생성.

### 2-6. 디스크 핫플러그 + ★영속화(persist)★
```bash
virtctl addvolume <vm> --volume-name=<dv-or-pvc>           # 임시(재부팅 시 사라짐)
virtctl addvolume <vm> --volume-name=<dv-or-pvc> --persist # 영구(재부팅 후에도 유지)
virtctl removevolume <vm> --volume-name=<dv-or-pvc>
```
> ⚠️ 함정: `--persist` 없이 붙이면 "지금은 보이는데 재시작하니 없어짐". 문제에 **"영구적으로/재부팅 후에도"** 표현 있으면 **무조건 `--persist`** (콘솔은 디스크 ⋮ → "Make persistent" 후 재부팅).
- **블랭크 디스크**: 콘솔 Add disk → Source **Blank**, 또는 DV `source: { blank: {} }`

### 2-7. StorageClass 지정 + 검증 (문제에서 SC 주면 반드시 명시)
```bash
oc get sc                                                # 이름 정확히 복붙 (오타=PVC 영원히 Pending)
# 검증
oc get pvc                                               # STATUS=Bound + STORAGECLASS 칼럼 확인
oc get pvc <dv> -o jsonpath='{.spec.storageClassName}{"\n"}'
oc get dv <dv>                                           # phase=Succeeded
```
> ⚠️ SC 생략 시 **default SC**로 생성됨 → 특정 SC를 요구했다면 오답.

**스토리지 체크리스트**
- [ ] URL import → VM 부팅
- [ ] gz `image-upload` → VM 부팅
- [ ] `guestfs` + `virt-sysprep` 골든 이미지
- [ ] 스냅샷 생성 → 변경 → 복원 (파일로 검증)
- [ ] `vmexport download` → `image-upload`로 새 VM
- [ ] `addvolume --persist` 영속화 + `lsblk` 검증
- [ ] SC 지정 후 `oc get pvc` Bound + STORAGECLASS 검증

## ★ 3. 네트워킹 보강 (50% → 목표 80%)

### 3-1. 네트워크 종류
- **기본 파드 네트워크** = `masquerade` (NAT, 별도 설정 없이 붙음)
- **2차(Secondary)** = **Multus + NetworkAttachmentDefinition(NAD)** → Linux bridge / OVN localnet / SR-IOV

### 3-2. 외부 접근 — `virtctl expose` (포트 안 줄 때 대응)
```bash
virtctl expose vm <vm> \
  --name=<svc> \
  --type=LoadBalancer \   # LoadBalancer / NodePort / ClusterIP(기본)
  --port=80 \             # 서비스가 받는 포트
  --target-port=80        # VM 안 실제 포트 (생략 시 --port와 동일)
```
> **포트 안 줬을 때**: `--target-port` 생략하면 `--port`와 동일. 기본 포트 추론 — 웹 80, HTTPS 443, **SSH 22**, RDP 3389.

**LoadBalancer 외부 접근 검증 (핵심)**
```bash
oc get svc <svc>                                                  # EXTERNAL-IP가 IP여야 함(<pending>이면 X)
oc get svc <svc> -o jsonpath='{.status.loadBalancer.ingress[0].ip}'
curl http://<EXTERNAL-IP>:80    # 또는  ssh <user>@<EXTERNAL-IP>
```
> ⚠️ 함정: ① EXTERNAL-IP가 `<pending>`이면 LB(MetalLB) 없음 → NodePort로 `<노드IP>:<3xxxx>`. ② expose 대상은 **masquerade + 실행 중**이어야 함(bridge/SR-IOV엔 안 됨). ③ `--target-port` 틀리면 서비스는 생겨도 연결 안 됨 → curl/ssh로 꼭 검증.

### 3-3. 멀티홈 VM (2차 네트워크) YAML 패턴
```yaml
spec:
  template:
    spec:
      domain:
        devices:
          interfaces:
          - name: default
            masquerade: {}
          - name: bridge-net
            bridge: {}
      networks:
      - name: default
        pod: {}
      - name: bridge-net
        multus:
          networkName: my-bridge-nad   # NAD 이름
```
> ⚠️ `interfaces[].name` 과 `networks[].name` 이 **짝이 맞아야** 함 (불일치=부팅 실패). 마스커레이드는 파드 네트워크에만.
- 구성 후 게스트에서 `ip a`로 인터페이스 확인, VM 간 `ping`.

**네트워킹 체크리스트**
- [ ] `virtctl expose --type=LoadBalancer` (target-port 생략) → EXTERNAL-IP → curl/ssh 검증
- [ ] NAD 조회/참조로 secondary network 연결
- [ ] 멀티홈 VM 구성 후 게스트 인터페이스 확인 + VM 간 ping

## 4. VM 생성·관리 유지 (75% → 90%) + cloud-init

```bash
virtctl start|stop|restart|pause|unpause <vm>
virtctl console <vm>     # 시리얼 (Ctrl+] 로 나옴)
virtctl vnc <vm>
virtctl ssh user@<vm>
oc get vm,vmi,dv,pvc
```
- 생성: Template / instance type+preference / 커스텀(URL·Upload·Clone)
- **RunStrategy**: `Always` / `RerunOnFailure` / `Manual` / `Halted`

**cloud-init — 계정·SSH키·초기 스크립트** (`userData`는 반드시 `#cloud-config`로 시작)
```yaml
volumes:
- name: cloudinitdisk
  cloudInitNoCloud:
    userData: |-
      #cloud-config
      user: cloud-user
      password: redhat123
      chpasswd: { expire: false }
      ssh_authorized_keys:
        - ssh-rsa AAAAB3Nza... user@host
      runcmd:
        - touch /etc/created-by-cloud-init
```
**검증 (이게 점수)**
```bash
virtctl ssh cloud-user@<vm>      # 또는 virtctl console <vm>
id cloud-user                    # 계정
cat ~/.ssh/authorized_keys       # 키
sudo cloud-init status           # done 이어야 정상
```
> ⚠️ `userData`는 **첫 부팅에만** 적용. `#cloud-config` 헤더 빠지면 통째로 무시.

## 6. 시험장 전술
- **지문 두 번 읽기**: VM·볼륨·네임스페이스·SC 이름 그대로 복붙 (오타가 0점 1순위)

- **네임스페이스 먼저**: `oc project <ns>`
- **시간 배분**: 스토리지부터 점수 확보 → 네트워킹 → VM관리. 막히면 다음으로
- **import/스냅샷은 먼저 트리거**해두고 다른 과제 진행 (완료까지 시간 걸림)
- **docs 활용**: apiVersion(`v1beta1` 등)은 제품 docs에서 복사

## 7. 막판 1분 치트시트
```bash
# 이미지 들여오기
URL → DataVolume http source (콘솔 "URL (creates PVC)")
gz  → virtctl image-upload dv <name> --size=NGi --image-path=FILE --storage-class=SC --insecure

# 골든 이미지 (봉인)
oc get pvc; virtctl guestfs <vol>; virt-sysprep -a /dev/vda

# 복제(Clone) — 콘솔=Actions→Clone / CLI는 아래 한 줄 (YAML 손으로 X)
virtctl create clone --source-name <원본> --target-name <사본> | oc apply -f -
oc get virtualmachineclone        # PHASE: Succeeded 확인
virtctl start <사본>              # ★복제는 자동시작 안 됨 → 수동 start
virtctl console <사본>            # 검증: hostnamectl(머신ID 바뀜) + last(로그 비었음)

# 내보내기 → 복원
virtctl vmexport download <export> --vm=<vm> --volume=<vol> --output=disk.img.gz
virtctl image-upload dv <restored> --size=NGi --image-path=disk.img.gz --insecure

# 핫플러그(영속화)
virtctl addvolume <vm> --volume-name=<dv> --persist
virtctl removevolume <vm> --volume-name=<dv>

# 네트워크 노출 + 검증
virtctl expose vm <vm> --name=<svc> --type=LoadBalancer --port=80   # target-port 생략=port와 동일
oc get svc <svc>; curl http://<EXTERNAL-IP>:80

# SC + 검증
oc get sc; oc get pvc <dv> -o jsonpath='{.spec.storageClassName}'

# 제어
virtctl start|stop|restart|console|ssh|vnc <vm>
oc get vm,vmi,dv,pvc,snapshot,nad,svc
```

## 8. 🆘 명령어 까먹었을 때 답 찾는 법 (시험장 안전장치)

> EX156은 **제품 docs 열람 가능**. 명령어 전체를 외우지 말고 **"첫 단어(키워드)" 하나 + `--help`**로 복원한다.

### 1순위 — CLI 내장 help (제일 빠름, 항상 가능)
```bash
virtctl <키워드> --help          # 예: virtctl vmexport --help
virtctl --help                   # 하위명령 전체 목록 (키워드 자체가 기억 안 날 때)
virtctl vmexport download --help # 더 구체적인 플래그
```
→ 사용법·플래그(`--vm`, `--volume`, `--output` 등)가 다 나옴. 보고 조립.

### 2순위 — 공식 문서 검색 (시험 중 열람 가능)
- 키워드로 검색: `virtctl vmexport`, `export virtual machine`, `image-upload` 등
- 명령어 예시가 통째로 나옴 → 복붙 후 **이름만 교체**

### 3순위 — 리소스 구조 확인
```bash
oc explain <kind>.spec           # CR 필드 설명 (예: oc explain dv.spec)
oc get <리소스> -o yaml          # 이미 만든 게 있으면 구조 참고
```

### "첫 단어"만 기억하면 되는 키워드 표
| 작업 | 떠올릴 키워드 | help 명령 |
| --- | --- | --- |
| 내보내기/다운로드 | **export** | `virtctl vmexport --help` |
| 업로드 | **upload** | `virtctl image-upload --help` |
| 골든이미지 | **guestfs** | `virtctl guestfs --help` |
| 외부노출 | **expose** | `virtctl expose --help` |
| 디스크 핫플러그 | **addvolume** | `virtctl addvolume --help` |

> **복원 예시**: "VM 디스크를 gz로 빼내야 해" → "export니까 vmexport" → `virtctl vmexport --help` →
> `download <이름> --vm=<vm> --volume=<vol> --output=disk.img.gz` 조립 → `oc get vm,pvc`로 실제 이름 확인 후 복붙.
>
> **핵심: 명령 전체가 아니라 키워드 한 단어만 기억 → `--help`로 나머지 복원. 패닉 금지.**

## 9. 🎯 영역별 핵심 명령 (시험 직전 손정리)

> 출제 4영역: **VM 생성·관리·모니터링 / 네트워킹 / 스토리지 / 골든이미지**

### 🥇 골든이미지 (봉인) — ★CLI 필수
```bash
oc get pvc                          # 볼륨 이름 확인
virtctl guestfs rhel-golden-volume  # guestfs로 디스크 열기
  virt-sysprep -a /dev/vda          # 고유정보 제거(봉인)
  exit                              # 봉인 VM 시작 금지!
```

### 📸 클론 / 스냅샷 / 복원 (대부분 콘솔)
- **Clone** = 콘솔 (Actions → Clone)
- **스냅샷 생성** = 콘솔 (Snapshots → Take snapshot) — VM 안 꺼도 됨
- **복원** = 콘솔(+CLI) — **VM 중지 후** Restore
- 복원 검증: 스냅샷 후 `touch update_failed.txt` → 복원하면 사라짐 (빈 파일 미리 만들기)

### 📤 볼륨 다운로드(export) — ★CLI 필수
```bash
virtctl vmexport download dev-server --vm=dev-server --volume=dev-server-volume --output=dev-server-disk.img.gz
virtctl vmexport download <VME이름>   # 이미 만든 export 이름으로 다운로드만
```

### 📥 업로드(image-upload) + VM 생성
```bash
# gz를 새 DataVolume으로 업로드 (SC는 문제에서 줄 때만)
virtctl image-upload dv dev-server-restored-disk --size=10Gi --image-path=dev-server-disk.img.gz
#   (SC 지정 예) --storage-class=ocs-external-storagecluster-ceph-rbd-virtualization
# 그 볼륨에서 VM 생성 (한 줄로!)
virtctl create vm --name=dev-server-restored --volume-pvc=src:dev-server-restored-disk | oc apply -f -
```

### 🌐 네트워킹 — 서비스 노출 / Route / Import
```bash
# 80→80 길 만들기 (ClusterIP)
virtctl expose vm hello-web --name=hello-web --type=ClusterIP --port=80 --target-port=80
# 외부 URL = Route (웹)
oc expose service/hello-web --name=<route이름>
# non-HTTP(SSH 등) = LoadBalancer
virtctl expose vm <vm> --name=<svc> --type=LoadBalancer --port=22 --target-port=22
```
- **Import(다른 클러스터 VM 가져오기)**: 주어진 URL에 image.gz + yaml → workstation에서 **scp로 yaml 복사 → yaml의 image url을 준 URL로 치환 → `oc apply -f x.yaml`**

> ⭐ **진짜 외울 2개(콘솔 불가): 봉인(guestfs+virt-sysprep) · export(vmexport download).** 나머지는 콘솔도 됨.
