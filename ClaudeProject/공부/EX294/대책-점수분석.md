# 📈 대책 · 점수 분석 (2차 시험 후)

> 합격선 210/300 (70%). 목표는 "약점 끌어올려 전 영역 60%+".

## 1. 점수 비교 (1차 → 2차)

| 영역 | 1차 | 2차 | 변화 | 문제 번호 |
|------|:---:|:---:|:---:|------|
| Install/configure control node | 100% | 100% | = ✅ | 1 |
| Manage content | 33% | **44%** | ↑ +11 🎉 | 11·14·15·16·17 |
| Use Roles & Collections | 39% | **48%** | ↑ +9 🎉 | 3·5·6·7·8·9 |
| Create plays and playbooks | 45% | 40% | ↓ -5 | 전반(플레이 구조) |
| Understand core components | 38% | 32% | ↓ -6 | 10·11·12 (when/loop/facts) |
| **Use modules for sysadmin** | 35% | **15%** | ↓↓ -20 🚨 | **4·10·12·13·14·16·18** |

## 2. 해석 — 방법은 통했다

- **공부한 곳(Content·Roles)은 둘 다 올랐다** → 노트+반복 방식이 유효.
- 롤은 이제 2등. 체감상 막혔어도 실제론 진전.
- **떨어진 곳(모듈·core·plays)은 상대적으로 덜 판 영역** = 다음 타깃이 명확.

## 3. 🚨 최우선 = 시스템관리 모듈 (15%)

35→15 급락. 원인 후보:
1. **시간 부족** — 앞(롤·content)에서 오래 끌다 뒤 모듈 문제를 못 풀었을 가능성 大
2. **검증 안 함** — 플레이북이 "돌아가긴 했는데" 요구 상태를 못 만듦 (idempotent/end-state 실패)
3. **become 누락** — /etc·패키지·사용자 건드리는데 권한 없어 조용히 실패

### 처방
- **문제 풀 때마다 3단 검증 습관**: `--syntax-check` → 실행 → **확인 명령**(`rpm -q`, `lvs`, `id`, `crontab -l`, `cat`)
- **모듈 문제는 짧다 → 먼저 푼다**: 4·12·13·18(cron)·14 는 빨리 끝나는 득점처. 시험 시작하면 **모듈부터**.
- 모듈 7개(4·10·12·13·14·16·18) 하루 1~2개씩 **손으로 반복** → 15%는 올릴 여지가 가장 큼.

## 4. 왜 점수가 안 오를까 (공통 원인 3가지)

1. **끝까지 못 푼다(시간)** → 문제 순서 전략 필요 (아래 5번)
2. **검증을 안 한다** → 만들고 실행+확인까지 해야 점수. `-C`(체크)·확인명령 습관화
3. **become/권한** → 플레이 맨 위 `become: true` 또는 ansible.cfg `[privilege_escalation]` 고정

## 5. ⏱️ 시험 순서 전략 (다음 시험)

> "쉽고 빠른 것 먼저, 오래 걸리는 롤은 뒤로"

```
1순위(빠른 득점): 1 설치 → 2 repo → 4 패키지 → 12 issue → 18 cron → 13 file
2순위(중간):      15 vault → 17 rekey → 11 template → 14 hwreport → 10 볼륨
3순위(오래걸림):  5·6 시스템롤 → 3 콜렉션 → 7 갤럭시설치 → 8 롤생성 → 9 롤사용 → 16 user
```
- 각 문제 **10~12분 넘기면 표시하고 넘어가기** (뒤에 다시)
- 마지막 30분은 **안 푼 것 + 검증**에 사용

## 6. 🎭 롤이 막히는 진짜 이유 & 처방

롤은 올랐지만 아직 48%. 막히는 지점은 대부분 **"세 종류를 헷갈려서"**:

| 롤 종류 | 언제 | 핵심 | 잘 틀리는 것 |
|------|------|------|------|
| **시스템 롤** (5·6) | timesync/selinux | `vars`+`roles`, **tasks 없음** | 변수명(README 안 봄), 롤이름 접두어 |
| **갤럭시 설치** (7) | requirements | `- name/src` + **`install -r`** | collection이랑 헷갈림, roles_path |
| **커스텀 롤 생성** (8·9) | apache | `init`+tasks+template, **호출 플레이북 별도** | hosts 위치, `roles:` vs `tasks:` |

### 롤 3대 실패 원인 → 처방
1. **롤을 못 찾음** (`role not found`) → ansible.cfg `roles_path` 확인 + 설치 위치 일치 (`-p`)
2. **롤은 도는데 아무 일도 안 함** → 시스템롤 **변수명 틀림**. 반드시 **README Example 복사**해서 값만 수정
   - `less /usr/share/ansible/roles/rhel-system-roles.timesync/README.md`
3. **롤 이름/구조 혼동** → 아래 한 장 규칙

### 롤 한 장 규칙 (외우기)
```
[시스템롤]  설치: yum install rhel-system-roles
            쓰기: vars(요구값) + roles(- rhel-system-roles.xxx)   ← tasks 없음!

[갤럭시롤]  requirements.yml:  - name / src   (--- 없음)
            설치: ansible-galaxy install -r requirements.yml

[커스텀롤]  생성: ansible-galaxy init roles/apache
            내용: roles/apache/tasks/main.yml (hosts 없음!) + templates/*.j2
            호출: 별도 플레이북 → hosts + roles: (- apache)   ← tasks 아님!

[콜렉션]    ansible-galaxy collection install <파일> -p <경로>   ← install -r 아님
```
