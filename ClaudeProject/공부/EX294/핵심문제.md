## 🔁 무조건 규칙 — 재부팅 유지 3종 (★ 2차 실점 원인)

> 채점은 **재부팅 후** 결과를 확인. 유지 옵션 빠지면 "풀었는데 0점".

| 대상 | 필수 | 없으면 |
|------|------|------|
| 서비스 | `enabled: true` | 재부팅 후 꺼짐 |
| **방화벽** | **`permanent: true`** (+`immediate: true`) | 재부팅 후 닫힘 → **curl 실패로 apache/balancer/phpinfo 0점** |
| 마운트/스왑 | **`state: mounted`** | 재부팅 후 사라짐 |

```yaml
ansible.posix.firewalld:
  service: http
  state: enabled
  permanent: true      # 재부팅 후에도 유지
  immediate: true      # 지금 당장도 적용
```
> 방화벽 안 열리면 **웹 문제(8·9) 통째로 날아감**. `permanent`+`immediate` 세트로 외우기.

## 8️⃣ 역할 생성 index.html.j2 — **변수 처리** — [전체](문제풀이/08-역할생성-apache.md)

### 딱 이것만 (`roles/apache/templates/index.html.j2`)
```jinja
Hello Apache from {{ ansible_hostname }} on {{ ansible_default_ipv4.address }}
```
> ⭐ **setup 출력에 보이는 이름 그대로** = 최상위 변수. 변환 필요 없어 제일 빠름.

### 🚨 여기서 에러났던 진짜 이유
`ansible localhost -m setup` 보면 `ansible_facts` 안에 **`ansible_hostname`** 으로 보임 →
그대로 `ansible_facts['ansible_hostname']` 라고 쓰면 **undefined 에러!**
```jinja
{{ ansible_facts['ansible_hostname'] }}   ❌ 에러 (접두어 붙이면 안 됨)
{{ ansible_hostname }}                     ✅ 최상위 변수 (추천, setup 이름 그대로)
{{ ansible_facts['hostname'] }}            ✅ ansible_facts는 접두어 뺌
```

### 변수 이름 대조표 (외우기)
| setup에 보이는 것 | ✅ 이렇게 쓰기 (추천) |
|------|------|
| `ansible_hostname` | `{{ ansible_hostname }}` |
| `ansible_default_ipv4` | `{{ ansible_default_ipv4.address }}` |
| `ansible_fqdn` | `{{ ansible_fqdn }}` |

> 한 줄로: **"setup에서 본 `ansible_xxx` 이름을 `{{ }}` 안에 그대로"**.
> IP만 뒤에 `.address` 붙이기. `{{ }}` 빼먹지 말기.

## 🔟 논리 볼륨 — **아래쪽 msg(rescue)** — [전체](문제풀이/10-논리볼륨생성-block-rescue.md)

### 📖 이해편 — block/rescue/debug/msg 개념부터

| 키워드 | 뜻 | 쉬운 말 |
|--------|-----|--------|
| `block` | 시도 | "일단 이거 해봐" (try) |
| `rescue` | 실패 시 | "안 되면 이거 해" — block이 **실패해야만** 실행 (except) |
| `debug` | 출력 모듈 | "화면에 글자 띄우기" (print) |
| `msg` | 그 글자 | debug가 띄울 **내용** |

> 한마디로 **try / except / print**. `block`=try, `rescue`=except, `debug: msg:`=print.

#### ⚠️ 제일 헷갈리는 것 = 들여쓰기
```
  - block:        ← 2칸 + 대시 (이게 task 1개!)
      - name:     ← 6칸 + 대시 (block의 자식 = 정상 시도)
    rescue:       ← 4칸, 대시 없음! (block과 세로 정렬 = block의 짝꿍)
      - debug:    ← 6칸 + 대시 (rescue의 자식 = 실패 시 할 일)
```
- **대시(`-`)는 `block:` 에만.** `rescue:` 는 대시 없이 **`block:` 과 세로줄 맞춤**.
- block 안 것들 / rescue 안 것들은 각각 **한 칸 더 들어간 `- ` 리스트**.

#### 🔁 흐름 (언제 뭐가 실행되나)
| 상황 | 실행 |
|------|------|
| vg 있고 1500m OK | block 성공 → **rescue 안 감** |
| vg 있는데 1500m 큼 | block 실패 → 미안 → **800m**(defined) |
| vg 자체가 없음 | block 실패 → 미안 → **not found**(undefined) |

---

### 딱 이것만 (rescue 3줄이 핵심)
```yaml
    rescue:
      - debug:
          msg: Could not create logical volume of that size
      - name: Create a logical volume of 800m
        lvol: { vg: research, lv: data, size: 800m }
        when: ansible_lvm.vgs.research is defined      # vg 있으면 800m
        ignore_errors: yes
      - debug:
          msg: Volume group not found
        when: ansible_lvm.vgs.research is undefined    # vg 없으면 메시지
```

### 🧠 암기 훅 — rescue = "미안 → 작게 → 없네"
1. **미안**: debug "Could not create..." (그냥 출력)
2. **작게**: 800m 생성 — **`is defined`** (vg 있을 때만) + `ignore_errors`
3. **없네**: debug "Volume group not found" — **`is undefined`** (vg 없을 때만)

> 막혔던 포인트 = 아래 두 debug/when. **defined=800m, undefined=not found** 짝으로 외우기.
> 조건 변수는 **`ansible_lvm.vgs.research`** (lvm→vgs→볼륨그룹이름).

### ❓ 왜 `when` 이랑 `ignore_errors` 를 넣나

**block(1500m)이 실패하는 이유가 2가지**라서, rescue에서 둘을 갈라줘야 함:
| block 실패 원인 | 원하는 대응 |
|------|------|
| ① vg는 있는데 1500m가 너무 큼 | 👉 800m로 다시 |
| ② vg `research` 자체가 없음 | 👉 800m도 못 만듦 → 메시지만 |

- **`when: ...is defined`** = "vg가 **있을 때만** 800m 시도" → ②(vg 없음)면 800m는 **skip**.
  이게 없으면 vg 없을 때도 800m를 시도해서 **또 실패**함.
- **`ignore_errors: yes`** = "이 task가 실패해도 **플레이 안 멈추고** 다음 줄로 진행".
  → rescue 안에서 800m마저 실패해도 마지막 "없네" 메시지까지 흐르게 하는 **안전장치**.

```
block 실패
   ├─ vg 있음(defined)   → 800m 만들기 ✅
   └─ vg 없음(undefined) → 800m skip → "Volume group not found" ✅
```
> 한 줄: **`when`=길 두 갈래로 나누는 스위치, `ignore_errors`=실패해도 안 멈추는 안전벨트.**

## 1️⃣1️⃣ 호스트 파일 생성 (`hosts.j2`) — [전체](문제풀이/11-호스트파일생성-template.md)

### 딱 이것만
```jinja
{% for host in groups['all'] %}
{{ hostvars[host]['ansible_facts']['default_ipv4']['address'] }} {{ hostvars[host]['ansible_facts']['fqdn'] }} {{ hostvars[host]['ansible_facts']['hostname'] }}
{% endfor %}
```
```yaml
# hosts.yml 안 template task
      when: inventory_hostname in groups['dev']
```

### 🧠 암기 훅 — "for → hostvars → IP FQDN name"
- 감싸기: **`{% for host in groups['all'] %}` … `{% endfor %}`** (열고 닫기 세트)
- 각 줄: **다른 호스트 정보라 `hostvars[host]`** 로 꺼냄 (내 정보 아님!)
- 순서: **IP · FQDN · hostname** (한 줄에 3개)

> 막혔던 이유 = `hostvars[host]` 빼먹고 그냥 `ansible_facts`만 씀 → 전부 내 값만 나옴.
> **"남의 집(host) 정보는 hostvars[host]로"** 만 기억.

## 1️⃣4️⃣ 하드웨어 보고서 — **vda / vdb** — [전체](문제풀이/14-하드웨어보고서생성.md)

### 딱 이것만 (못 외웠던 디스크 경로 · 최상위 변수)
```jinja
{{ ansible_devices.vda.size | default('NONE', true) }}
{{ ansible_devices.vdb.size | default('NONE', true) }}
```
> 최상위 변수 = setup 출력의 `ansible_devices` 그대로. (같은 값: `ansible_facts['devices']['vda']['size']`)

### 🧠 암기 훅 — "장치들 안에 vda, 그 안에 size"
- 경로 3단: **`ansible_devices` → `vda`(또는 vdb) → `size`**
- 디스크는 여러 개라 **`devices`(복수)** 밑에 `vda`, `vdb` 가 들어있음
- 없을 수 있으니(vdb 없는 노드) **`| default('NONE', true)`** 필수 (`true` 꼭!)

### 나머지 값도 같이 (최상위 변수)
```jinja
{{ inventory_hostname }}                             # 호스트 이름
{{ ansible_memtotal_mb | default('NONE', true) }}    # 메모리
{{ ansible_bios_version | default('NONE', true) }}   # BIOS
```
> 막혔던 이유 = `devices.vda.size` 3단 경로가 안 외워짐. **"devices > vda > size"** 계단으로 그림 그리듯.
> 확실치 않으면: `ansible localhost -m setup -a 'filter=ansible_devices'` 로 구조 직접 보기.
